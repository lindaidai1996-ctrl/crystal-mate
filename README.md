# Crystal Mate 商品管理后台

Next.js App Router、React、Ant Design、Prisma 和 PostgreSQL 构成的单项目后台。当前仅实现管理员商品管理；商品均为库存 0/1 的孤品。管理界面支持中英切换，商品内容只保存中文原文。

## 本地运行

要求 Node.js 20.9+、npm，以及 PostgreSQL 16+。可以用 `docker compose up -d postgres` 启动数据库，也可以使用本机 PostgreSQL。

1. 复制 `.env.example` 为 `.env`，设置 `DATABASE_URL`、`DIRECT_URL` 和随机生成的 `AUTH_SECRET`。本地图片使用 `MEDIA_STORAGE=local`。
2. 执行 `npm install` 和 `npm run db:deploy`。
3. 本地示例配置 `ADMIN_USERNAME=admin`、`ADMIN_PASSWORD=123456`。执行 `npm run db:admin` 创建管理员；如果已有且仅有一个管理员，会更新其账号和密码。
4. 执行 `npm run dev`，打开 `http://localhost:3000/zh/login`。

数据库连接池场景中，`DATABASE_URL` 使用池连接地址，`DIRECT_URL` 使用直连地址；本地可设置为同一个地址。`123456` 仅供本地开发，生产环境必须改用独立的强密码、托管数据库和 HTTPS。

## 图片存储

本地模式把已验证的 JPG、PNG、WebP 写入 `public/uploads`，单张最多 8 MB、每件商品最多 12 张。该目录已加入 `.gitignore`，仅供开发使用；生产环境禁止本地模式。

部署到 Vercel 时设置 `MEDIA_STORAGE=cos`，并配置 `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_BUCKET`、`COS_REGION`。浏览器使用限时签名 URL 直接向 COS 上传，因此桶的 CORS 规则需要允许 `PUT` 和 `Content-Type` 请求头；允许来源为 `*` 时无需随网站域名变更规则。商品图片通过本站 `/api/images/` 接口由服务端从私有桶读取，仅管理员登录后可见，无需 COS 自定义域名或公有读权限。上传凭证有效期 5 分钟；上传后服务端检查对象存在且不超过 8 MB，再允许关联商品。更换或删除商品图片不会立即删除 COS 对象，后续应定期清理未引用对象与过期上传记录。

## 图片批量录入

物料管理中的「图片批量录入」支持单图识别、多条目裁剪、价格校对及采购入库。默认接入 DeepSeek 的图片模型 `deepseek-flash`；服务端设置 `DEEPSEEK_API_KEY`，可选设置 `DEEPSEEK_BASE_URL`、`DEEPSEEK_VISION_MODEL`，然后重新启动服务。当前图片接口说明见 [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision)。不要使用不支持图片的型号替代视觉模型。

后续换模型可通过 `IMPORT_VISION_LABEL`、`IMPORT_VISION_BASE_URL`、`IMPORT_VISION_API_KEY`、`IMPORT_VISION_MODEL` 配置第二个模型，在导入页选择。兼容模型需支持 Chat Completions 的 `image_url` 图片输入及 JSON 输出；Base URL 必须使用 HTTPS，并按服务商要求保留 `/v1` 等前缀。不兼容该协议的模型可新增适配器，沿用统一的坐标、条目和入库数据结构。所有密钥均为服务端环境变量，浏览器只能获取模型名称和配置状态。

图片导入的原图存放在 `material-imports/sources/`，确认入库时生成的裁切图存放在 `material-imports/crops/`；普通商品、物料及附件上传继续使用 `images/`。这些是同一 COS 桶内的对象前缀，无需手动创建目录；本地模式在 `public/uploads/` 下使用相同结构。已有 `images/` 图片和历史导入记录继续可用，不自动迁移文件。裁切图入库后是正式物料图片，原图也可能成为采购批次附件，不能按“临时导入文件”直接配置自动删除。

上传整图并确认发送给模型后，先保存导入任务，再自动开始识别，无需预先裁剪或手动画框。识别后在候选总览中查看全部饰品缩略图、价格和异常提示，点击条目校对。原图由服务端以图片字节发送到所选模型，不需要公开 COS 桶。校对页面与新增/编辑物料共用基础信息、采购计算、售价策略和图片表单区块，支持标签、尺寸、备注及额外附件；识别范围会作为第一张物料及采购图片。完整表单随导入草稿保存，确认入库时保留所有填写的字段。校对页面可重画饰品和价格范围，添加/拆分条目、合并所选条目，补齐名称、分类、库存单位、数量、采购价、供应商和批次，并关联已有物料。图片价格可逐条指定为采购价或售价；标记为售价时必须另填采购价。图中展示数量不作为采购数量。克单位继续使用现有两位小数采购规则。

「保存草稿」不会增加库存；确认入库后，每条采购写入和导入回执在同一事务中完成，重试不会重复增加库存。首次入库后供应商和批次固定，已入库条目不可在草稿中修改。部分失败时保留已经成功的回执和剩余候选，修正后重试。原图会附在采购批次中，便于核对。

识别请求由当前 HTTP 请求执行，最长 120 秒；任务和草稿保存在数据库中，不依赖浏览器内存。关闭页面后可以从最近 50 次导入中恢复；若进程中断，租约到期后可手动重新识别。当前没有独立后台队列、款式自动命名或透明底抠图。模型仅提供候选，坐标与价格均需人工校对；真实图片上的准确率应在配置密钥后实测。

## 部署

将仓库连接 Vercel，配置生产环境变量、托管 PostgreSQL 和 COS。首次部署前在可访问数据库的环境运行 `npm run db:deploy` 和 `npm run db:admin`；后续数据库变更先执行迁移再发布对应应用版本。Vercel 自动执行 `npm run build`。不要在预览部署和生产部署间共享可写数据库。上线前从中国大陆网络实测访问速度及稳定性。

## 验证

`npm run typecheck`、`npm run lint`、`npm test` 和 `npm run build` 验证静态质量。首次运行浏览器测试前执行 `npx playwright install chromium`；若本机已有 Chrome，可设置 `PLAYWRIGHT_CHROME_PATH` 为浏览器可执行文件路径。

端到端测试使用独立数据库：先创建名称以 `_test` 结尾的 PostgreSQL 数据库，设置 `E2E_DATABASE_URL`、`E2E_USERNAME`、`E2E_PASSWORD`，再运行 `npm run test:e2e -- tests/e2e/materials.spec.ts`。命令会在测试库部署迁移、创建或更新测试管理员，再启动 Playwright；默认测试端口为 3100，可用 `E2E_PORT` 调整。测试服务使用 `.next-e2e`，能与日常开发服务同时运行；测试上传默认使用本地图片存储。脚本拒绝将项目正常数据库 URL 用作测试库。

### DIY 商品照片识别

商品列表和非蛋面商品编辑页提供「AI 识别 DIY 用料」。每份草稿接受同一商品的 1–6 张照片（JPG/PNG/WebP，每张最多 8 MB，识别时合计最多 24 MB），复用上方视觉模型配置；模型必须支持多图输入及 JSON 输出。识别分为多视角部件拆解、名称/别名/分类候选检索，以及最多 12 张候选参考图片比对。候选不自动确定采购批次，外观相似也不代表材质、尺寸或成色相同。

用户可框选、补录、合并或排除部件，选择物料及实际采购批次，填写每件用量和成本，再逐项确认。克重、隐蔽部件及工费需要人工核实；缺少成本不会按零计算。草稿自动保存，识别失败可重试。全图重识别保留已确认及已排除项；单部件重识别需先取消确认。

确认入库会在一个数据库事务中创建商品或为已有 DIY 商品添加制作记录，保存成本快照、原图和校验清单，并增加成品库存；重复提交返回同一份回执。沿用现有规则，不自动扣减物料库存。新建商品默认不发布；为已有商品补充制作记录不会改变原商品售价或发布状态。

使用前运行 `npm run db:deploy` 和 `npx prisma generate`，重启 Next.js。新增草稿表为 `DiyImageImport`。图片导入草稿和正式库存隔离；未入库草稿可删除，已入库记录保留作为追溯依据。检索暂以最近 5000 个物料及 1000 个蛋面为限，超出时页面会提示人工补充搜索。

### 蛋面 Excel 批量导入

蛋面管理中的「Excel 批量导入」接受 `.xlsx`，每张表最多 300 条、文件最多 50 MB。浏览器解析工作表并自动对应常见表头，可手动选择工作表、表头行号和列对应关系。支持 WPS `DISPIMG`、新版 Excel 单元格内图片和旧版随单元格定位的图片；按图片引用关系关联原表行号，不按媒体文件顺序猜测。支持 JPG/PNG/WebP，其他浏览器可解码格式转为 PNG，每张最多 8 MB。图片链接和缺失图片会提示处理。

预览时可逐行修正或新建标签，再上传图片保存草稿并勾选确认导入。表格编号忽略，确认导入时使用系统编号预留机制。名称使用“艺名-类型”，无类型时使用“未知”；修正价非空时优先，否则取售价，两者为空使用 0，并保存为自定义价格。尺寸取最后一行非空内容交给现有尺寸识别器。成本可空；魔盒款式匹配不到时为未知。发布状态只同步小红书的两个标记，系统自身默认不上架。卖出库存为 0，其余为 1；作为历史库存导入，来源保持未登记。

草稿和逐行回执保存在 `CabochonExcelImport`，商品、库存记录、编号和回执在同一事务写入；重复点击和重试返回已有商品。重复文件通过文件哈希和工作表名称提示，不按商品名覆盖历史商品。蛋面 Excel 导入、新建/编辑页面的图片上传及图片替换统一使用同一 COS 桶下的 `cabochons/images/` 前缀，无需创建新桶或公开访问；这些图片是正式商品图片，不应配置为临时文件自动删除。历史 `images/` 和 `cabochon-imports/images/` 图片及草稿继续可用，不自动搬迁对象。本地存储沿用相同目录结构。启用前执行 `npm run db:deploy` 和 `npx prisma generate`，并重启开发服务。

### 商品名称与蛋面类型标签识别

商品新建、编辑时修改名称并离开输入框，会使用 AI 从已有标签库匹配多个标签，也可以点击“重新匹配标签”。蛋面 Excel 导入在生成预览时按“蛋面类型”批量识别，保留“艺名-类型”的商品名原文；待导入行可以重新匹配或手动选择多个标签。识别到“粉云母”等颜色类型时，会同时补齐已有的“云母”基础标签；缺少标签会提示人工处理，不自动创建。

默认复用服务端 DeepSeek 配置，可通过 `TAG_RECOGNITION_BASE_URL`、`TAG_RECOGNITION_API_KEY`、`TAG_RECOGNITION_MODEL` 覆盖为支持 Chat Completions 和 JSON 输出的文本模型，配置后重启服务。识别结果只进入商品表单或导入草稿，保存商品/确认导入后才写入商品标签；商品编辑会保留已有及手动选择的标签，只替换本次编辑期间自动添加的标签。识别失败可重试或手动选择。
