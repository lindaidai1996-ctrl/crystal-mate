# 双账号操作追溯实施计划

目标：共享业务数据，同时能区分录入者、最后修改者及每一次业务变更的操作账号。

## 执行步骤

- [x] 1. 基础：后端认证身份、事务内审计、记录归属、历史数据人员未知。
- [x] 2. 核心业务：商品、材料、采购、DIY、库存及其关联明细。
- [x] 3. 批量与配置：导入、识别、批量操作、供应商、批次、字典和价格设置。
- [x] 4. 草稿与账号：个人草稿、历史草稿单独显示、识别发起人与入库确认人、账号设置事件。
- [x] 5. 查看：独立操作记录页面、筛选、详情、业务对象的归属及历史入口。
- [x] 6. 验证：隔离数据库验证、事务回滚、级联删除、敏感字段、格式/类型/lint/单元测试、开发库迁移。

## 约定

- 记录操作账号 ID、账号和当时昵称；创建人与业务归属不同。
- 每个请求使用统一操作编号，批量操作和关联库存变化可一起查看。
- 数据库触发器捕获实际变更；审计与业务处于同一事务，回滚不留成功记录。
- 子表变更关联主业务对象；删除后保留日志及对象名称、编号。
- 密码和密码散列、会话版本、任务令牌不写入日志；大体积草稿/识别内容仅记录变更事件。
- 历史记录不推测创建人；数据库脚本写入标记为系统操作。
- 不记录普通浏览请求；无业务字段变化的更新时间刷新不生成日志。
- 线上迁移和代码发布在开发验证后执行；当前计划先交付开发环境可验证结果。

## 已完成验证

- 36 张业务表安装事务内审计；67 个现有写入接口携带经过认证的账号身份。
- 创建者和最后修改者使用账号 ID、账号及当时昵称快照；子表操作关联主业务对象。
- 相同请求关联同一操作编号；支持嵌套写入、数组事务、批量操作、级联删除。
- 不变的图片、附件、标签及 DIY 用料不再无条件删除重建，减少重复记录。
- 历史草稿通过明确领取归属账号；普通草稿的读取、编辑、删除按当前账号过滤。

- 商品、材料列表及详情，供应商、采购批次、识别/导入任务均提供归属和历史入口。
