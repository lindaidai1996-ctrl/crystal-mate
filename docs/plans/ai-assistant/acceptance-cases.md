## 验收方法与门槛

### 服务与语义分开验证

1. P2 先验证确定性查询、字段关联、日期和汇总，不调用模型。
2. P3 评估候选覆盖与语义判断；对每个预期采购行记录在解析、候选、判断哪一步丢失或误入。
3. P4 使用 mock 工具验证编排边界，再记录真实 DeepSeek 调用；mock 通过不等于模型通过。
4. P6 对冻结基线做稳定回归，再对变化中的开发库只读联调；两种报告分开。

### 首版交付门槛

- REAL-01～REAL-10：冻结基线的集合与精确汇总一致。主案例 recall=1、precision=1，这是该有限基线的验收值，不是对任意问题的准确率承诺。
- SEM-01～SEM-14：确定、排除、待确认和非法输出处理均符合预期，不能靠把全部候选纳入来提高召回。
- TIME/FACT/FLOW：对应边界均验证；日期、数量、金额、引用 ID 与权限范围不得有已知错误。
- 每条正式结果有有效字段证据；完整性状态真实，待确认和未评估不混入确定汇总。
- 真实模型评估记录模型名、接口、提示词/规则版本、参数、输入快照版本及运行次数。固定核心问题重复运行 3 次作为首轮稳定性观察；记录每次差异，不能只保留一次成功结果。
- 任一核心门槛未达成时保留失败记录与待办，不勾选相应阶段通过。性能与成本阈值在测量后确定。

### 指标口径

- 召回率：预期确定集合中实际返回的比例；对采购问题默认按采购行 ID 比较。
- 准确率（precision）：返回确定集合中属于预期确定集合的比例；空集合时明确记录，不用除零结果掩盖失败。
- 待确认准确性：该待确认的是否仍待确认，是否错误升级为确定事实。
- 候选覆盖与完整性：预期记录是否进入候选、遍历与判断是否完成。
- 事实一致性：日期、渠道商、数量、金额、库存与原始字段及业务计算一致。
- 追问正确性：保留、替换、删除的条件与预期一致。
