## 版本化规则

`semantic-policy.ts` 提供 v1 策略、语义条件归一化、召回词和可解释的确定性判定。输入仍是受控的 `semanticConditionSchema`，不承担任意自然语言解析。配件/配饰在制作物料语境归一为用途；圆珠、散珠、桶珠、药片、随形、提溜、勒子、藏扣等可为用途证据，但不把所有 Material 或分类视为配件。圆珠查询不扩大到桶珠，提溜/吊坠不做全局同义替换。裸词松石不自动改成绿松石。

规则读取真实目录名称、别名、分类/祖先、标签与备注/描述，返回逐条件 include/exclude/uncertain、依据和原因；每条证据必须来自候选原字段。不读取图片、价格、联系人或账号推断语义。材质区分自身材质、颜色/仿制和搭配用途；字段冲突保留 uncertain，不按优先级覆盖。缺失或规则不支持为 uncertain，不凭艺名补猜。业务文本只作数据，不能修改查询或规则。

这只是可测的规则执行器与 P3-03 的规则依据，不代表模型相关性判断或任意中文语义已完成。负向条件保留三态，证据不足不能通过逻辑取反变为肯定。每个条件 AND：有冲突/证据不足需单独保留；明确不符且无冲突时可排除。

## 多路候选

`queryAssistantRecall(request, assistantQuery)` 独立服务复用 P2 硬范围和账号鉴权。单次读取完整有界硬范围，为目录字段命中及分类祖先命中记录真实来源，联合完整范围遍历去重；不把软语义变成硬标签或分类条件。采购身份按采购行保留，不能按名称或目录合并丢批次。

返回原候选分页信息及每条候选的 `sources`：`name/aliases/category/category_subtree/tag/notes/full_scope`。各来源带实际命中词和候选中的真实字段证据。`full_scope` 表示完整范围后备覆盖，非关键词匹配或语义纳入。没有词命中的候选也保留，供后续判断。查询/语义条件、规则版本、工具标识和认证账号绑定运行；详情仍限定同账号已读候选。全量来源计数独立于当前页。

物料分类祖先通过真实 parentId 链提供，先检查断裂、循环及扫描上限；祖先证据使用实际分类 ID 和字段值，不制造别名。商品分类没有树。继承分类可用于召回，但子级与祖先材质冲突仍需保留不确定。

当前有界完整范围最多 5000 行，分类树扫描最多 5000；超过即明确预算错误，不用 Top-K 伪装全部。P3-04 已提供该边界内的分批判断/预算恢复，仍未实现超过此硬范围上限的数据库分块召回；P3-05 实测后暂缓索引或向量检索。候选遍历完整不等于语义判断完整。

实现、验证及限制详见下文；当前仅交付内部服务。

## 服务与规则入口

- `normalizeSemanticConditions(conditions)`：校验受控条件，返回制作语境用途的规范词及召回词，不改变硬条件。当前自身材质规则仅覆盖 `SEMANTIC_POLICY.materialLabels` 的显式词表；裸词松石、艺名、颜色词和其他未覆盖材质均保留待确认。新数据仍会被完整范围召回，规则未覆盖不意味着应排除。
- `assessSemanticCandidate(candidate, conditions)`：返回逐条件判断和与实际候选绑定的 `decision`；没有条件或没有真实证据时 `decision=null`。决策证据上限 50，超出报 `SEMANTIC_EVIDENCE_BUDGET_EXCEEDED`，不静默丢弃可能冲突的依据。
- `queryAssistantRecall(request, assistantQuery)` / `getAssistantRecallDetails(request, input)`：分别为专用候选分页、同账号已读详情入口。`recallPageSchema` 在原候选页上增加 `policyVersion`、与页内 key 一一对应的 `sources` 及完整运行的 `sourceCounts`。一行可以命中多路，来源计数不能直接相加当作去重总数。
- 召回工具独立使用 `CandidateRuns` 存储，每账号最多 4 个运行、全进程 32 个、10 分钟到期；候选/采购/召回三个工具合计最多 96 个运行。快照失效、跨账号、跨工具、换条件均拒绝，不静默重查。P4 前仍需处理跨实例存储或同进程路由。

上述补充不改变 v1 业务定义，不将未知升级确定，不引入任何业务 ID 特判。模型在未知规则上可依据真实字段作判断，明确规则分歧或字段冲突降为 uncertain 并保留双方证据；无事实或无语义条件也不输出确定相关性。没有可引用字段而无法产生合法判断的条目仍未评估，不能伪造空证据。
