# P2-04：采购明细与汇总

2026-11-16。P2-04 已完成，以下为本轮新增契约和消费约定。

输入为 `{query: assistantQuerySchema, selectedPurchases?: purchaseRef[]}`；`query.subject` 必须为 `purchases`，继承多渠道商、多对象、地点、日期、分类等硬范围。可选采购行集合用于后续已确认结果的精确选择；省略表示整个硬范围，显式 `[]` 表示空选择，重复/范围外引用拒绝。该集合不证明模型语义正确，P3 仍需校验判断来源与覆盖率。

同一只读一致性事务先复用候选范围校验，再读取采购事实。物料金额优先已有 `purchaseTotalAmount`，否则只有数量和采购单价均已知时相乘；商品金额仅用采购 `quantity × unitCost`。未知保留 null。所有计算使用高精度 Decimal；十进制字符串至少两位小数，保留乘积精度，不先把每行金额四舍五入后再加总。数量按真实单位分组，采购行与去重目录分别计数。

当前两类采购表均没有独立币种字段，商品 `Product.currency` 属于目录售价，不能推断采购币种。数据库读取采用当前业务的 CNY 默认，逐行标记 `currencyBasis=business_default`；汇总记录默认币种行数。纯汇总支持已记录币种和未知币种各自分组，不能跨币种相加。此默认不是已核实的历史币种事实，未来多币种采购需显式字段及独立授权的迁移。

每页返回采购明细、完整选定集合的总体/渠道商/目录分组汇总，以及范围候选数和遍历状态。分页和重试不改变汇总；币种、未知金额、不同数量单位各自保留。软语义不提前筛除候选，不将采购工具汇总称为语义查询的最终总额。

复用 P2-03 的账号隔离、运行有效期、候选预算与游标校验；采购工具和精确选择也绑定在范围摘要内。首次查询冻结必要采购事实，后续页使用同一观察时刻的快照。换选择、改范围、运行过期或淘汰均不能静默续查。当前为服务层能力，没有 HTTP 路由、模型工具注册或界面。

## 接口与生命周期

实现位于 `src/lib/ai-assistant/purchase-contracts.ts`、`purchase-data.ts`、`purchase-summary.ts`、`purchase-runs.ts`、`purchase-service.ts`。入口为 `queryAssistantPurchases(request, input)`，每次调用先 `requireAccount`；新运行在 `READ ONLY`、`RepeatableRead` 事务中取值，事务 20 秒、单语句 8 秒超时。

输出为 `purchasePageSchema`：版本、运行 ID、观察时间、完整请求、当前页明细、下一游标、遍历/判断完整性及 `summary`。`summary` 包含 `basis`（`hard_scope` / `selected_purchases`）、选择前硬范围候选数、总体、按渠道商和按目录分组的汇总。金额组保留 `knownAmount`、`unknownAmountEntryCount` 和 `businessDefaultCurrencyEntryCount`；数量组保留 `knownQuantity`、`unknownQuantityEntryCount`。只有某组金额未知时，已知小计可以是 `0.00`，未知计数仍大于 0，不代表采购金额为零。

物料 `code=null`，采购单位来自当前目录 `Material.unit`；商品为 `PIECE`。批次日期为日历日期字符串。现有表没有历史单位/币种快照，不能据此声称查到历史采购当时的独立单位或币种凭据。不返回剩余库存、售价、联系人、地址或账号字段。

计算使用独立配置的 50 位有效数字 Decimal，不修改全局 Decimal 精度，不经 JavaScript 浮点数累计。采购单位数量与采购单价的乘积最多 4 位小数，全部保留；例如三行 `0.0025` 的精确和是 `0.0075`。金额与数量字符串至少 2 位小数，去除多余末尾零；最终展示舍入由后续界面处理，不能以先舍入的每行金额反算事实。

P2-03 的 `CandidateRuns` 增加了内部 `queryWithData` 与 `snapshotData` 扩展，把经过 schema 校验的采购事实/汇总与候选身份一起冻结；原候选接口不变。运行数据读取仍校验账号及有效期；返回值复制，调用者修改当前页或源对象不能污染快照。采购与候选工具使用各自的运行存储，每个存储最多 32 个运行、每账号 4 个，10 分钟过期；两工具合计最多 64 个运行。工具标识和选择集合额外绑定摘要，不能将候选工具游标用于采购工具，也不能在续页时更改已选择采购行。

单次硬范围和选定采购集合仍最多 5000 条；即使只选择少量行，也先完整校验硬范围，不能以选定行数小为由绕过候选扫描上限。选择超出硬范围报 `PURCHASE_OUTSIDE_SCOPE`；采购行消失或目录/批次/渠道商关系不一致报 `PURCHASE_SNAPSHOT_CHANGED`，不能把部分行当作完整汇总。其他地点、引用、预算、游标及运行错误沿用 P2-03。后续 P4 仍需统一跨进程存储/路由，并映射可恢复错误状态。

非空结果在本工具结束时只完成事实读取/遍历，语义 `evaluation=not_started`。调用者提交的精确采购选择只限制汇总集合；不自动代表所有候选都经过正确判定。后续 P3/P4 必须验证实际候选判断，把排除、待确认、未评估数与确定集合汇总一起展示。
