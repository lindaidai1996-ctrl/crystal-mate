# AI 助手：扩充与同步维护指南

创建日期：2026-11-16（Asia/Shanghai）。用于开发其他业务功能时判断是否需要同步修改 AI 助手；持续维护，不作为功能完成记录。当前进度以[执行计划](../ai-assistant.md)和最新源码为准。

## 先判断改的是数据还是能力

**现有结构下增加业务记录，通常不需要改助手代码；改变字段、关系、业务含义、权限或查询能力，需要评估同步。** 新字段不会因为加入 Prisma 或页面就自动成为助手可查询、可解释的字段。

助手从业务数据库读取事实，使用名称、别名、分类、标签、备注/描述等已接入字段提供证据，不依靠硬编码的商品名单。新增一种水晶不需要重新训练模型。但“数据能查到”不等于“自然语言判断已验证”：截至本指南创建时，地点/字典、候选/详情、采购汇总与当前库存服务已实现，P3-01/P3-02 已增加有限词表的确定性语义规则和多路候选服务；P3-03/P3-04 已增加受控 JSON 模型相关性判断、累计覆盖和执行预算，P3-05 已根据实测暂缓语义索引；模型工具注册、对话和助手界面仍待开发。新术语仍可被完整范围召回，规则未覆盖时保留待确认，不能据此声称模型已理解。

## 变更判断表

| 业务变更                                                 | 助手是否需要同步                 | 检查或修改内容                                                                                                                   |
| -------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 新增商品、物料、渠道商、采购记录；修改已有记录           | 通常不需要改代码                 | 新查询读取当前数据库；已有运行快照不自动刷新。名称、分类、别名、材质描述和地址应有真实依据。                                     |
| 新增分类、子分类、标签或已有字段内的别名                 | 通常不需要改代码                 | 字典和分类树动态读取；核对层级与记录关联。新增分类不代表该分类全部自动属于“配件”等用途概念。                                     |
| 新增内部术语、特殊材质表达，改变“配件/成品”等业务定义    | 评估语义规则与案例               | 优先补充真实别名/描述；定义改变时同步规则及版本、正例/反例/待确认案例。规则管理界面尚未实现，不假设可直接配置或自动学习。        |
| 新增/改名/删除字段、调整表关系、软删除或有效状态         | 检查相关服务，按用途同步         | 检查 Prisma 查询、筛选、证据字段白名单、详情及契约。新增硬度、产地等字段不会自动供助手使用；新增但不用于助手的字段说明原因即可。 |
| 新增枚举值、计量单位或单位换算                           | 需要同步相关能力                 | 检查契约枚举、数量分组、单位含义、换算与未知值；当前采购/库存契约显式列举单位。不能把“新增标签”与“新增单位枚举”视为同一种扩充。  |
| 改采购日期、实际采购人、地点、历史地址或业务归属         | 需要同步相关查询与口径           | 调整硬条件、关联、时间边界、地点精度与历史事实说明；录入者仍不能代替采购人。                                                     |
| 改采购成本、折扣、运费、税费、多币种、退货金额或利润公式 | 需要同步相关查询与汇总           | 后端 Decimal 计算、金额来源、币种分组、未知值及展示说明。当前采购币种为明确标记的 CNY 业务默认，新增采购币种字段后需接入真实值。 |
| 改库存扣减、DIY 用料、盘点、退货、预留或可售库存         | 需要同步库存能力                 | 复用权威库存口径，检查采购量、来源余量、目录总库存和单位。当前 DIY 用料不自动扣库存；以后增加扣减时须验证助手不会再次扣减。      |
| 新增订单、客户、退货、销量、利润等业务模块               | 若要助手支持，需新增能力         | 增加受控查询工具、输入/输出契约、权限和业务计算，再接入模型及界面；只开发业务页面不会让助手自动支持。未接入时明确能力边界。      |
| 改账号、租户、角色、记录可见范围、价格隐私或审计         | 必须复核，按变化同步             | 服务端鉴权、返回字段、模型输入、结果展示、日志、运行摘要及会话隔离；不能只隐藏页面上的值。当前共享业务数据不等于未来可继续共享。 |
| 仅改布局、配色、交互，查询字段与口径均未变               | 通常不需要                       | 若涉及助手详情链接、结果展示字段或隐私交互，再检查对应接入。                                                                     |
| 数据量增长、批量导入、多实例部署或新增检索/缓存          | 评估容量和一致性，可能需要改代码 | 按下节检查候选/批次规模、超限、内存快照、跨实例运行及索引生命周期。不能仅增加常量就认定扩容完成。                                |

## 数据规模与部署的触发条件

以下是 2026-11-16 的实现边界，调整时同步更新本节及对应契约文档，不把这些数值当成永久目标。

- **候选查询**：单次硬范围最多 5000 条，目录按款、采购按采购行计数。首次读取完整有界候选并冻结到进程内存，再分页返回；接口分页不代表数据库已采用可无限扩展的分批读取。超限返回 `CANDIDATE_BUDGET_EXCEEDED`。
- **地点与字典**：地点扫描最多 5000 家渠道商；字典每个来源最多扫描 5000 条，超限明确不完整。分类树遍历也有预算。详见[地点与字典](reference-resolution.md)和[候选查询](candidate-query.md)。
- **当前库存**：候选/结果和所选物料的全部库存批次扫描均有 5000 条上限。即使只查少量款式，历史批次很多也可能触及 `STOCK_BUDGET_EXCEEDED`，详见[库存查询](stock-query.md)。
- **运行快照**：候选、采购、多路召回及相关性执行各自使用独立进程内存状态（相关性执行另复用一个私有召回存储），10 分钟到期，每账号每工具最多 4 个运行、每工具最多 32 个。新增/修改业务记录后发起新查询才能取得新观察值；库存新调用重新读取。进程重启、淘汰、过期或请求转到另一实例，需要显式重启运行。正式接入对话/HTTP 或改多实例部署时，复核共享运行存储或可靠的同进程路由方案。

**总商品数超过 5000 不等于所有查询失效；应看每次筛选后的候选数量，以及库存涉及的批次数量。** 当常用查询接近上限、频繁超限、响应变慢、内存/并发压力增大或模型成本明显上升时，记录规模、耗时和用量，再评估数据库分批处理、索引、多路候选召回、后台任务或共享运行存储。

向量检索暂缓接入，依据当前真实/构造案例无候选漏查、约 10 秒/44 行的模型判断及实际 token 用量作出决定；详见[索引评估](semantic-index-assessment.md)及其中重评触发条件，不声称向量性能已测。若引入，新增/修改/删除数据、批量导入与规则/索引版本变化都要有更新及过期回退机制；金额、数量和库存仍回业务库读取。任何优化都必须保留未完成状态，不能用第一页或 Top-K 宣称“全部”。性能和语义索引评估分别关联执行计划 P6-03、P3-05。

## 每次功能开发怎么收尾

1. 按判断表确定助手影响。仅新增记录或纯 UI 改动时，可说明“无需同步”及原因，不为此额外开发助手功能。
2. 影响现有查询正确性、业务口径或权限时，同步相关契约、数据读取/汇总及必要案例；新业务能力暂不接入时，在功能交接与助手计划中留下明确缺口，不能声称已支持。
3. 对尚未实现的助手层，更新规则、契约或后续任务的验收要求；接入时仍需真实验证，文档更新不等于模型已理解。
4. 选择与改动相称的验证：需要时运行相关 `tests/unit/ai-assistant-*.test.ts`、类型/lint 检查；业务数值变化对照页面权威函数，必要时用开发库只读脚本复核。简单文档/UI 变更不新增 E2E，修改文件按仓库要求格式化并运行 `npm run format:check`。
5. 契约语义不兼容时升级版本并检查调用者；规则定义变化时维护规则版本及案例。`development-baseline.json` 是冻结验收快照，普通录入或导入不覆盖它；需要新基线时独立记录日期、范围和差异。

在对应功能的交付说明或交接文件中使用下面的简短记录；无需单独建重复台账。需要后续任务时，从[执行计划](../ai-assistant.md)链接该记录。

```text
AI 助手影响：无需同步 / 已同步 / 待同步（选择一项）
原因与范围：变更了哪些数据、字段、规则或能力；哪些查询受影响。
同步内容或后续任务：相关代码/文档，或尚未接入的能力与下一步。
验证及边界：实际运行的检查；尚未覆盖的业务库/模型/界面行为。
```

## 模型与执行维护（P3-03～P3-05）

- 入口：`relevance-contracts.ts`、`relevance-model.ts`、`relevance-runs.ts`、`relevance-service.ts`；契约见[模型执行](model-evaluation.md)。字段/规则变动需复核模型最小 DTO、证据索引、规则分歧保护和冻结分类祖先适配器，不能只更新提示词。
- 语义字段只作数据；不发送采购金额/库存/账号/完整地址。备注仍是自由业务文本，尚无自动隐私识别，新增敏感字段须单独审核模型 DTO。不能从客户端/模型接受候选或账号。
- 执行失败/超时仍累计调用与 token 预留；缺失判断保留未评估，不能把 uncertain 当未评估或纳入确定汇总。继续/取消校验账号、runId、revision；缓存/异步改造必须保留代际检查。
- 默认 batchSize=10、累计 20 调用/200000 预留 tokens/5000 判断；每步最多 2 调用、60 秒，单次 30 秒，输入 100000 字节、输出 4000 tokens。服务输入可在严格 schema 上限内调整累计预算；原始计数不清零。多实例/进程重启仍不支持恢复，过期重启须重新读取事实。
- 模型配置可独立用 `ASSISTANT_RELEVANCE_API_KEY/BASE_URL/MODEL`；缺省复用 `DEEPSEEK_API_KEY/BASE_URL/VISION_MODEL`，最终默认 deepseek-flash。模型/提示词改变后至少重复核心三次并保留差异，不把 mock 或确定性规则结果当模型验证。当前只验证 JSON、非流式相关性，不代表 P4 工具/流式/多轮通过。
- 回归命令：相关 `ai-assistant-relevance*.test.ts`，离线 `check-ai-assistant-relevance.ts`；真实调用需显式 `--real`，开发库需隔离启动器加 `--dev`，不能在普通测试中隐式收费或联网。索引离线评估用 `check-ai-assistant-index.ts`，依赖已保存实测报告。
