# P2-06：只读查询工具边界

当前服务入口：地点解析、字典搜索、候选查询/详情、采购查询、库存查询。每次入口都调用现有 `requireAccount`，账号来自服务器会话；严格 Zod 输入拒绝 actor/owner/account/自由 SQL。当前业务数据共享，认证账号只用于运行归属，不等于采购人或目录所有者。不存在助手对话存储，未来会话隔离仍由 P4-03 实现。

现有 `db` 为 `withDatabaseAudit` 包装，`withAuditRoute` 仅建立操作上下文，认证由 handler 内执行；`requireAccount` 经 `requireAdmin` 在该上下文中写入服务器认证的 actor。查询没有业务 mutation，不创建审计业务行。不得为只读助手新增数据库写入审计或绕过认证。后续真实 HTTP 工具路由继续使用当时路由封装。

本轮跨服务验证使用真实 `requireAccount`、`withAuditRoute`、`withDatabaseAudit` 代码和 mock 会话/数据库，核验先认证、最小字段、账号间运行/详情/游标拒绝、共享业务数据与业务文本不改变范围。开发库复核单独使用实际只读事务，不能把 mock 当成真实登录 HTTP 或已完成未来对话隔离。

各服务字段边界见对应说明。地点只返回命中片段，不发送完整联系资料；字典仅真实字典字段；候选仅身份和字段证据；采购仅采购事实与汇总；库存仅数量及单位。业务备注可能含自由文本，当前不得声称已实现自动隐私脱敏；对模型发送策略仍需 P4/P5 按字段最小化。

后续 P3 候选服务也遵守同样边界。验证结果见下文完成记录。

## 完成记录

- 地点/字典服务本轮加上显式 `READ ONLY` / `RepeatableRead`，语句 8 秒、事务 10 秒超时；其他事实服务沿用只读一致性事务。无新增 HTTP 路由或业务写入。
- 新增跨工具测试 28 项，覆盖全部 8 个服务入口（包括候选/召回详情）的认证与未知参数拒绝、6 种查询的最小 DTO 和审计上下文、并发 actor 隔离、共享业务事实及账号/工具间运行和详情拒绝。真实认证/审计代码配合 mock 会话/数据库执行，不把测试数据库 stub 当真实业务权限环境。
- 实际开发库使用 `withDatabaseAudit` 包装客户端，验证 transaction-local actor 在 READ ONLY 事务中存在、事务结束后不残留。该脚本的 actor 是只读验证标识，不是真实登录账号；没有调用 mutation、创建业务审计记录或修改业务数据。结果见[脱敏报告](verification/2026-11-16-p2-06-p3-01-02.json)。
