## P2-06 边界结论

每次服务入口真实 `requireAccount`，经现有 `requireAdmin` 获取服务器会话，严格输入拒绝账号、actor/owner、自由 SQL。`withAuditRoute` 建上下文，现有 `withDatabaseAudit` 注入事务级 actor；本轮没有修改这些共享封装。地点/字典增加显式 READ ONLY，其他事实查询保留现有只读事务。

当前业务数据共享，两个认证账号可以读相同事实，运行/游标/详情按账号隔离。没有助手对话存储，不能称会话消息隔离已实现。候选/采购/召回使用独立存储，跨工具游标拒绝；详情只接受该账号运行中已读到的精确身份。

DTO 不暴露账号、密码、电话或额外关系字段；地点仅命中片段，候选不返回完整地址。备注本身是业务自由文本，未实现自动隐私识别/脱敏，后续模型输入仍须字段最小化。数据中命令式文字不能改变硬条件或认证范围。

## P3-01 / P3-02 契约与选择

- v1 查询/候选/采购/库存原接口保持兼容；未改变原规则定义，只把既有业务口径落成可执行策略。`normalizeSemanticConditions` 接受受控条件，制作语境配件/配饰归一，不承担任意中文问题解析。
- `assessSemanticCandidate` 区分自己材质与搭配用途、颜色/仿制/否定；材质字段、祖先与子级冲突保留 uncertain，未知不经否定变成 include。圆珠/桶珠精确分开，提溜/吊坠不做全局同义；制作形态不能覆盖所有物料/分类。
- 自身材质规则使用明确有限词表，不将艺名或任意新类别当材质。未覆盖表达保留 uncertain，新增记录仍能通过完整范围召回；规则可扩展，不宣称当前有限规则覆盖所有珠宝术语。此限制已同步维护指南。
- 返回逐条件解释与真实候选证据绑定的 decision，无条件/无证据时 decision=null；决策证据超过 50 明确 `SEMANTIC_EVIDENCE_BUDGET_EXCEEDED`，不悄悄截掉冲突依据。P3-03 仍需模型判断和覆盖率核验。
- `queryAssistantRecall` 接受原 assistantQuery，先完整验证硬范围，再联合 name/aliases/category/category_subtree/tag/notes/full_scope 来源。原始 ID 不硬编码，祖先来自真实 parentId 链并验证循环、断裂与预算；使用实际分类 ID/字段作为证据。
- 当前所有不超过 5000 行的硬范围完整读取，软语义不会过滤掉缺标签或无关键词候选。`full_scope` 只是覆盖后备，不是语义匹配依据。来源计数允许多路重叠，不能相加冒充去重候选数。按目录类型/ID 或采购行身份保留，同物料多采购不合并。
- `recallPageSchema` 保留原候选页与完整性字段，新增 policyVersion、页内 key 对应的 sources、全运行 sourceCounts；非空运行 evaluation 仍 not_started。独立 RecallRuns 绑定工具/策略/查询/认证账号，分页及重试不改变来源计数。
- 新召回存储每账号 4 个/全进程 32 个/10 分钟有效；候选、采购、召回合计最多 96 个运行。仍为进程内，失效必须显式重启。P4 前需共享运行存储或可靠的同进程路由。
- 超过 5000 硬范围/分类树或 200 条候选字段证据明确预算错误，不以第一页/Top-K 代替全量。大范围优化、预算恢复、模型执行覆盖及向量索引仍分别属于 P3-04/P3-05。
