输入 `{mode, query, selectedItems?, selectedPurchases?}`，沿用 v1：

- `catalog_current` 接受目录或历史采购 query。目录选择使用 `selectedItems`，采购选择使用 `selectedPurchases`，不允许交叉、重复、错类型或范围外引用。省略代表硬范围全部；显式空选择为空，不扩大范围。
- 采购 query 先完整校验日期/地点/渠道商/分类/对象等硬范围，再按选定采购行确定目录。目录按类型与 ID 去重，重新读取该目录全部当前批次，不把日期、地点或渠道商条件带入库存扫描。
- `purchase_remaining` 仅物料采购，逐行返回 `purchasedQuantity`、`remainingQuantity`、真实采购/批次与目录身份。商品只有总库存，没有采购行余量字段，此模式拒绝商品，不能拿商品总库存或采购数量冒充来源余量。
- 目录模式使用与业务页面相同 `materialStockSummary`、同样的批次遍历顺序；`knownStock`、未知批次数与总批次数分别返回。商品直接读 `Product.stock`，不按历史采购重算。数量汇总 Decimal 按 STRAND/BEAD/GRAM/PIECE 分开，未知对象数/批次数保留。
- 独立的库存查询每次重新观察，不使用候选/采购运行快照；拒绝 cursor，`pagination.limit` 不限制本工具完整输出。候选、选择和输出最多 5000；目录全部批次扫描也最多 5000，读取 5001 探测超限后报 `STOCK_BUDGET_EXCEEDED`，不返回截断结果。
- 返回范围候选数、选定候选数、去重目录数、`traversal=complete` 和 `semanticEvaluation=not_performed`。选择不等于语义判断正确。范围/引用/地点/数据库失败原样传播，不伪装为空结果。
- 每次先真实 `requireAccount`，不接受调用者账号/owner/SQL；当前共享业务库不能按录入者推定采购人。只读事务为 `RepeatableRead`，事务 20 秒，语句 8 秒；没有跨账号缓存可引用。

## 必须保留的业务发现

`MaterialBatchEntry.remainingQty` 是当前业务页面事实来源。库存更正（单条/批量）直接写该值；修改采购数量时 `correctedRemainingQuantity` 保留此前已用数量。查询不重放调整 delta，也不用初始采购量覆盖当前余量。

当前 `product-sources.ts` 的 DIY 创建/编辑保存用料/成本，不自动扣减物料批次库存；使用单位还可能是某串拆出的颗数，不能简单从采购串数减去颗数。库存工具读取当前持久化余量，没有新增写库存逻辑。这是对现有实现的核对结论，不声称本轮实现了自动 DIY 消耗。余量和采购量不同也不能单凭这两个值推断原因。
