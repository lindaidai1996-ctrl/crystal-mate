## 消费约定

- 地点 `exact_place` 仅按明确名称/地址匹配确定；备注提及、区域一致以及明显否定/历史/附近语境单列待确认。区域 `area` 仅完整区域名称确定，部分名称待澄清；不建立“荔湾 = 荔湾广场”别名。
- 多渠道商全部保留；输出只含 ID、名称、区域和实际字段的匹配片段位置，不发出完整地址/备注/联系信息。片段不能冒充 P2-01 的完整字段原值证据。
- `status=resolved` 表示有字段依据的确定范围已解析，可以同时有单列的区域待确认者。只有待确认且无确定者时 `needs_clarification`；完整且没有任何匹配时返回确定空范围。
- `resolvedLocationDistributorIds` 仅消费**服务端本次解析结果**，不接受模型提交的同形对象作为可信结果。P2-03 将返回 ID 与用户明确渠道商取交集；交集为空时保留 `in: []`，不能省略地点限制或把空数组塞回模型查询输入。
- 每来源扫描最多 5000 条，额外读 1 条探测截断；截断为 `incomplete`。地点不能生成完整筛选，字典不能报告总数或展开不完整树。`scannedCount` 不含探测行。
- 字典支持物料分类、商品分类、标签、渠道商名称；仅物料分类有真实别名/树，其余不伪造。字典命中不自动成为硬条件，目录物料/商品的别名召回留给 P2-03/P3。
- 分类树保留父 ID、根到父的祖先以及全部后代；检测断裂/环后抛错。字典分页提供 `totalMatches` 与 `hasMore`，类型/ID 稳定排序；后续用 ID 时仍需回源验证。
- 地点文字判定为保守字面实现，复杂自然语言、历史地理、到访行为和采购人不能据此推断。当前共享业务数据不按录入者过滤。
