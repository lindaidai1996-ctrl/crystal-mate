# P2-03：候选与详情查询

日期：2026-11-16。实现：`src/lib/ai-assistant/candidate-contracts.ts`、`candidate-data.ts`、`candidate-runs.ts`、`candidate-service.ts`。沿用查询契约 v1；未新增路由、工具注册或界面。

## 服务调用与字段

- `queryAssistantCandidates(request, input)`：输入为 `assistantQuerySchema`，返回 `candidatePageSchema`。每次调用先执行 `requireAccount`；首次查询在 `READ ONLY`、`RepeatableRead` 事务内解析硬范围并读取必要字段，后续页从服务端快照读取。当前业务库共享，账号用于认证和运行隔离，不作为采购人或目录所有者。
- `getAssistantCandidateDetails(request, {runId, candidates: [{item, purchase}]})`：只允许同账号、未过期运行中**已读到的精确目录/采购组合**，最多 100 条，不接受重复、未知、未读或错配组合。返回运行 ID、观察时间及详情；不提供绕过硬范围的任意 ID 查询。
- 详情包含 `candidate`、`code`、`batch`、`distributor`。物料没有商品编码，`code=null`；目录查询的 `purchase/batch/distributor=null`，采购查询保留真实采购行及批次、渠道商引用。
- 候选证据包含目录名称、真实别名、备注/描述、建档时间、直接分类名称（物料分类另有真实别名）、直接标签名称；采购另有采购建档时间、批次名称/日期/建档时间、渠道商名称/建档时间，以及商品采购备注。分类/标签各自使用真实实体 ID，不伪造目录嵌套字段或不存在的物料采购备注。
- 不返回价格、采购数量、库存、账号、电话、微信、地址等额外字段。金额/数量由已完成的 [P2-04](purchase-query.md) 提供，库存工具属于 P2-05；图片/规格等展示字段可按 P5 需求扩展，当前详情用于补查判断字段与真实关联身份。

## 硬范围

所有条件之间 AND；同类 ID 内 OR。显式物料/商品、标签、分类、渠道商 ID 必须存在，否则 `REFERENCE_NOT_FOUND`，不能当成完整空结果。引用存在性在与候选相同的一致性事务内验证。当前没有按录入者或历史操作者过滤。

- 地点直接消费本次事务读取的服务端解析结果，不接受调用者提交“已解析 ID”。完整确定的地点 ID 与显式渠道商 ID **取交集**。无匹配或交集为空时保留 `in: []`；目录的渠道商约束为存在对应采购关联。
- 地点仅待确认时报 `LOCATION_NEEDS_CLARIFICATION`；扫描不完整时报 `LOCATION_INCOMPLETE`。均不扩大范围、不返回完整空页面。范围解析规则和 5000 条扫描保护见[地点解析](reference-resolution.md)。
- 物料分类仅在 `includeDescendants=true` 时展开真实后代，环/断裂报 `INVALID_CATEGORY_TREE`；商品分类没有树。只指定某一类型的分类/目录 ID 时，另一类型保持显式空范围。
- 采购日期只筛 `batch.receivedAt`，UTC 零点承载日历日期，采用 `[from,to)`；建档时间按 `entity` 筛目录、采购行、批次或渠道商，以实际瞬间比较。
- `semantic` 保留在运行范围摘要内，**不提前转为名称、标签等硬条件**。主案例读取完整 44 条候选，绿松石/配件的判断留到 P3。

## 稳定分页与完整性

首次查询把硬范围内必要字段冻结为一个不可变候选快照；后续页和详情均使用该次观察值，不混入运行期间的新增、删除或改名。采购按采购类型、采购行 ID 排序，目录按目录类型、目录 ID 排序，比较使用固定字节序；采购行不按目录合并。服务报告硬范围内全部候选总数；读取数与去重目录数分别累计。

游标必须对应当前认证账号的运行、归一化查询摘要和**已签发的页尾位置**。摘要包含账号、版本、硬条件、软语义和规则版本；对象键/集合数组顺序归一化，不含游标和页大小，因此可调整 `limit`，不能修改业务条件。随机摘要、伪造/未签发位置、末行续读、换范围均拒绝。已签发游标允许重试；不会重复累计。重放较早页面时，计数仍表示本运行累计已读前缀，若运行已读完则无下一游标；调用者按身份合并页面，不能简单累加重试的页大小。

单次最多 5000 条候选（两种类型合计）。数据库每个来源最多读 5001 条以探测超限，超限抛 `CANDIDATE_BUDGET_EXCEEDED`；不保留或返回截断视图，不把第一页或 Top-K 伪装成全量。分类树读取也有同样保护。查询、超时、预算等错误需由后续编排层展示为失败/未完成，不能转为空结果。

非空范围只完成候选遍历，`evaluation=not_started`、`notEvaluated=readCandidates`、`stopReason=running`；不表示语义判断完成。确定空范围才返回遍历和判断均完成、所有计数为 0、`stopReason=null`。

## 生命周期与后续接入限制

快照只保存在当前服务进程内，有效期固定 10 分钟，每账号最多 4 个、每个工具存储最多 32 个，按创建顺序淘汰。超时、淘汰、进程重启或请求落到其他进程时报 `RUN_RESTART_REQUIRED`；必须显式发起新运行，不从游标静默重查。过期快照在下一次访问或创建运行时清理。P2-04 采购工具使用独立存储，两个工具合计最多 64 个运行。

这是当前独立服务的有界实现，尚非跨实例持久会话存储。接入 P4 HTTP/工具循环前，应统一运行存储或确保同进程路由，并将这些错误映射为可恢复执行状态。运行详情是观察时刻字段，不承诺实时事实；采购汇总/库存应按各自契约重新读取。认证范围目前为共享数据；如将来引入租户或业务权限，必须把服务端权限范围/版本加入摘要，并逐次复核可访问范围。
