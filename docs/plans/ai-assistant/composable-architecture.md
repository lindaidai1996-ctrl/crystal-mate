# P7—P10 可组合查询与回答架构

2026-11-18。当前入口为 `conversation-service.ts` → `runComposableAssistant`，版本 `assistant-agent-v1`。原 `orchestrator.ts` 的固定循环保留给历史协议回归；新 HTTP 消息和旧执行恢复均进入新循环，不自动选择旧循环兜底。

## 执行与接口

唯一模型函数为 `next_action`。参数经过严格联合校验；错误参数返回安全字段错误供模型在累计预算内修正，错误函数名、提供商失败及非法 JSON 不自动重试。

| action       | 输入与行为                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------ |
| capabilities | 当前能力、来源和缺口，无业务查询                                                                             |
| lookup       | 已认证字典查询，返回真实渠道商/分类/标签及依据                                                               |
| query        | 必须指定 subject/itemTypes，提交原 v1 条件 patch；reset 清除旧条件及表达，purpose 区分主查询、查找和对照查询 |
| present      | 独立修改 format/fields/concise/strictFields；不替代业务查询                                                  |
| transform    | 引用本执行签发的集合，进行筛选、排除、缺失、去重、排序、Top N、分组、latest、compare 或 join                 |
| inspect      | 从集合读取最多 50 行预览，不代表完整列表                                                                     |
| sources      | 返回已签发集合/行的真实来源、查询范围、理由和允许的字段证据                                                  |
| clarify      | 保存澄清问题，等待新消息                                                                                     |
| answer       | 文字连接、建议与数据块，引用实际事实，不接收模型编造的数值/链接                                              |

现有会话路由及 message/continue/retry/cancel、鉴权、同源、审计、revision/CAS、150 秒租约保持。默认每命令最多 12 次编排模型调用、200000 保守预留 tokens、120 秒；可配置上限为 20 次/500000/120 秒。显式继续获得新的命令预算，但执行累计调用和预留成本保留。相关性模型独立限制累计预算，检查点继续累计尝试及成本，不能因新查询/恢复清零。预留值不是提供商实际计费 tokens。

每次工具调用前保存成本和执行归属，取消后的保存失败阻断下一模型请求；上游已发出的请求及费用不能撤销。查询/整理/present 保存带预签发集合 ID 的 journal；恢复先重读业务数据并重放，保持本执行引用 ID，校验证据后复用语义判断。失败、取消、数据变化、超时不会把旧结果当实时事实。

## 事实与业务口径

集合包含服务端 UUID、最多 5000 行、观察时间、查询来源、父集合、完整性和警示。每执行最多 12 个集合/累计 20000 行；超限明确暂停。查询/整理默认预览 10 行，inspect 最多 50 行；旧预览压缩后仍保留集合 ID、计数和工具选择，回答数据块由后端展开整个集合。

金额、数量、库存、差额和百分比使用后端 Decimal。分组自动补齐币种、单位及必要身份；名称不能代替目录/渠道商 ID。库存重复出现在多条采购行时只计一次目录库存，来源余量按采购行计。未知值单独计数，不能作为零进行完整比较。

latest 保留最近同日多条记录；价格比较要求同一货品、规格、单位及币种，有缺失或同日不同价时不可比较。期间比较支持空时期、出现/消失、基期为零及未知金额；不完整集合不能作全量期间比较。不同查询的观察时间保留，不宣称同一事务快照。

join 为一对一左连接，使用真实身份键，右侧重复须先整理；不得覆盖身份/单位/币种。未匹配字段为未知，不补零。排序和 Top N 按可比币种/单位分开处理。

排序分区随事实集合保留，因此 sort 和 take 分属两次工具调用时仍按币种/单位取排名。金额或库存含未知记录时，显示已知值必须标明“已知部分”，不能因用户省略未知计数字段就显示成完整总值。

## 回答与会话

`QueryState.task` 保存表达偏好和可重放整理操作；跨集合 compare/join 不把旧集合 ID 留作下一轮操作。新查询读取当前事实，历史回答保存原观察值。

`AnswerDocument` 使用 `answer-v1`：paragraph/advice 包含连接文本及事实引用，data 引用整个集合并指定 names/list/table 与字段。名称、数字、单位、日期、规格和链接由事实填充；字面数字、URL、不存在引用和多余字段拒绝。模型有一次受预算限制的修正机会；再次失败或修正预算不足，按用户要求字段输出确定性兜底并明确提示。

用户指定“只/仅这些字段”时 strictFields=true，名称模式始终严格；一般汇总解释/建议允许引用相关的真实计数和未知信息。兜底优先使用主查询/整理后的集合，不能因刚读取对照集合就替换为另一期间。

仅名称：按目录身份去重，同名不同目录不合并；单一匹配物料采购行链接批次，多行链接目录。数据块只有名称，隐藏金额、库存、图片、固定汇总和非必要币种说明；待确认等结论限制必须保留。长列表每页 100 条，分页不丢失集合其余记录。

每条助手消息保存完整回答，浏览器不再只展示“查询完成”。查询时间、范围、来源和执行详情按需展开。模型自然语言推理仍可能误解业务：引用验证只能验证来源和数值，不证明所有文字推断正确。

## 隐私与兼容

隐私关闭时只发送本题需要的授权事实。隐私开启时不发送历史自由文本、名称、渠道商、成本、金额、价格或受保护答案；集合预览仅保留身份、规格、日期、数量/单位/库存等白名单。禁止受保护字段的整理计算及字典文本；语义匹配需要读取业务名称，隐私开启时明确待确认，不绕过限制调用相关性模型。

浏览器隐私切换立即隐藏旧快照并中止在途请求，同时对服务端当前执行进行 CAS 取消，阻止继续发送旧隐私上下文。历史自由文本和生成答案在服务端隐私投影中整体移除；关闭隐私后查看的是历史快照，不重新生成历史事实。

复用现有助手表 JSON，不增加数据库迁移或业务表。消息 DTO 增加可空 answer；旧消息保持原状态展示，旧结果可展开查看。原始检查点、账号、模型输入和集合内部结构不通过浏览器 DTO 暴露。模型/HTTP/运行记录继续最小化凭据、联系方式与外部 URL；不声称具备通用敏感文本识别。
