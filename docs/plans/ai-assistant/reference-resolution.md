# P2-02：地点与字典解析

日期：2026-11-16。输入/输出契约与实现位于 `src/lib/ai-assistant/reference-contracts.ts`、`reference-resolution.ts`、`reference-service.ts`。这是查询契约 v1 的附加工具 schema，不改变既有查询字段含义。

## 地点

- 输入复用 `hard.location`：`text` 和 `kind: exact_place | area`。
- 确切地点：渠道商名称/地址中的文字匹配可以确定；同区域、备注提及，以及带否定、历史、附近等限定的匹配只列待确认。已知区域名称不能通过 `exact_place` 冒充具体地点。
- 区域：只用渠道商 `area` 的完整名称确定；部分名称只提供待确认建议，不推断行政上下级。
- 一地点可以返回多渠道商，确定集合与待确认集合分开。扫描完整且有确定匹配时，`status=resolved` 表示有依据的确定范围已解析；待确认者仍单列且不进入该范围，不承诺现实地理资料完整。只有待确认者时必须澄清；完整扫描且无任何匹配时是确定空集合。
- 输出只含渠道商 ID、名称、区域及匹配片段证据，不输出完整地址、备注或联系信息。片段证据使用 `field/matchedText/start/end`，对应原字段的字面位置，**不是** P2-01 的完整字段原值证据，不能混作语义判断证据。
- `resolvedLocationDistributorIds` 只接受完整且已解析的结果，返回显式 ID 数组（可以为空）；未完成/待澄清抛错。它是内部辅助函数，必须传入服务端本次生成的解析结果，不能信任模型提交的同形对象。P2-03 已在同一只读事务内解析地点并与显式渠道商条件取交集，见[候选查询说明](candidate-query.md)；空数组对应 `in: []`，不可省略筛选或塞回拒绝空数组的模型输入。

上述文字判断是保守的确定性匹配，不是自然语言地理推理；未覆盖的复杂表述仍需后续语义澄清。当前地址不证明历史到访或采购当日位置。

## 字典

- 输入：`text`（允许空字符串列出字典）、非空去重 `kinds`（`MATERIAL_CATEGORY` / `PRODUCT_CATEGORY` / `TAG` / `DISTRIBUTOR`）、`offset` 与 `limit`。
- 读取当前库的名称和真实别名；只有物料分类实际拥有别名和树关系。商品分类、标签、渠道商不伪造别名或层级。物料/商品目录别名召回由 P2-03/P3 的候选查询接入。
- 名称/别名按去除首尾空白、忽略大小写的字面子串匹配，提供精确/包含标记及原值字段证据。不自动把“松石”定义为“绿松石”，不把字典命中自动变成硬条件。
- 返回匹配节点、原始父 ID、按根到父排列的祖先引用和所有后代引用；只对物料分类扩展树，检测环或断裂并报错，不静默漏掉后代。同名跨类型节点保留。
- 以类型、ID 的固定顺序分页，返回全部匹配数和 `hasMore`；当前页不冒充全部字典。不同请求可能观察到字典变更，后续使用 ID 时仍须回源验证。

## 服务边界

服务调用 `requireAccount(request)` 后才访问数据库；当前与业务页面一样共享业务数据，账号不作为采购人或业务所有者筛选。地点和字典服务只读取必要字段，无写操作。P2-06 已统一加上显式 `READ ONLY` / `RepeatableRead` 事务、语句 8 秒/事务 10 秒超时；复用现有认证/审计包装，见[工具边界](tool-boundaries.md)。读取每个来源最多 5001 行，超过 5000 行明确标记 `incomplete`，拒绝生成完整地点筛选；字典扫描不完整时不生成匹配总数或树展开。此上限是可见执行保护，不是 Top-K 的全量保证。

`scannedCount` 表示实际参与解析的行数，不含用于探测截断的额外哨兵行。字典的 `hasMore` 仅用于扫描完整后的结果分页，扫描不完整时应先处理 `status=incomplete`，不能根据 `hasMore=false` 宣称已读完。

只读开发库复核命令：`node scripts/with-dev-db.mjs tsx scripts/check-ai-assistant-references.ts`。脚本独立校验连接目标与实际库名/账号，在 `READ ONLY`、`RepeatableRead` 事务中读取，不输出原地址、备注或联系信息。2026-11-16 14:37（Asia/Shanghai）复核得到 7 个确定渠道商、2 个区域待确认者，确定 ID 集合与冻结基线一致，分类别名命中正确；详见[验证记录](verification/2026-11-16-p2-02.json)。

本任务不新增 HTTP 路由、模型工具注册或助手界面；P2-03 消费已解析的 ID，P2-06 再完成整体工具权限/审计边界验证。实际验证结果和数据来源以本轮交接为准。
