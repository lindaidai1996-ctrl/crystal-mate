## 目标与范围

用户可以用自然语言查询商品、物料、渠道商、采购记录和当前库存，支持继续追问。首个端到端里程碑：

> 帮我找下这个月我去荔湾广场买了哪些绿松石相关的配件。

必须识别“配件/配饰”的表达差异，纳入属于制作物料的绿松石圆珠等记录，不能强制要求同名标签。最终结果能解释纳入依据，并关联真实业务明细。

首版交付文字对话、语义匹配、只读查询、连续追问、结果明细、完整性状态、业务汇总和回归验证。语音转文字随后接入同一条查询链路，语音播报再独立增加。

## 技术方案与约束

1. 继续使用现有 Next.js、TypeScript、Prisma、PostgreSQL、Zod、Ant Design 和 DeepSeek。
2. 优先评估 AI SDK 管理工具调用和流式对话；依赖引入前验证实际模型/接口兼容性。自行实现受控调用循环也可，记录选型依据即可。暂不预设 LangGraph、Dify 或 MCP 为依赖。
3. 查询链路：理解问题 → 解析业务实体和语义范围 → 找全候选 → 基于字段证据判断 → 查询真实明细 → 后端汇总 → 展示结果和口径。
4. 时间、地点、权限作为受控查询边界；“配件”等软语义不能在召回前变成必须存在的标签。即使硬条件来自模型，也要由后端校验。
5. 范围较小时分页读取并检查全部候选。大范围结合名称、别名、分类、标签、备注召回；任何截断都要暴露未完成状态。不得用 Top-K 或第一页冒充全部。
6. 语义检索是否引入，由验收样例中的漏查情况决定。后续引入向量索引时，明确生成、更新、删除、版本和过期回退策略；实时事实仍读取业务库。
7. 模型只能调用注册的业务工具，不能执行自由 SQL。查询、鉴权、数据范围校验、金额与数量计算都由后端完成。
8. 语义结论分为纳入、排除、待确认；未评估单独记录。模型必须引用返回过的实体 ID 和字段证据，不能生成不存在的记录。
9. 会话归属使用认证账号；会话消息和筛选条件不等于业务数据归属。“录入者”不等于“采购人”。
10. 本计划中的路径和接口名称是建议，落地时结合当时源码调整并更新文档。不要将初始快照当成持续不变的业务数据。

### 第二阶段：业务查询工具

依赖：P1-01～P1-06。

- [ ] **P2-01 定义查询契约。** 用 Zod 定义时间范围、实体引用、硬条件、语义条件、分页/游标、证据与完整性结构。区分 `purchaseDate` 和建档日期。验收：无模型也能表达主案例；非法 ID、日期和参数可拒绝。
- [ ] **P2-02 地点与字典解析。** 查询渠道商、地址、分类树、别名和标签。支持一地点多供应商，区分确切地点与较大区域。验收：基线中的 7 个地址命中者可找到，另外 2 个不能凭区域擅自纳入。
- [ ] **P2-03 候选与详情查询。** 在授权范围内分页获取物料/商品及相关字段，保持稳定顺序；给出全部候选计数和遍历状态。验收：主案例的 44 条候选不丢失，空范围和跨页不重复。
- [ ] **P2-04 采购明细与汇总。** 支持多个渠道商、多个对象、日期区间；明细按采购行保留，目录身份可聚合。金额采用 Decimal，未知字段与不同单位分别处理。验收：冻结基线的 11 条明细、1897.60 元及分单位数量可复算。
- [ ] **P2-05 当前库存查询。** 复用库存计算，区分采购数量、来源批次剩余量、同物料全部库存。验收：批次用量和库存更正后口径与现有业务页面一致。
- [ ] **P2-06 工具边界验证。** 复用当时的认证/审计封装；工具仅提供必要字段，确认会话之间的数据范围。运行必要的服务层测试及格式、类型、lint 检查。验收：不依赖 E2E 即可验证核心查询与权限边界。

阶段出口：查询服务可独立调用，事实和汇总正确，不依赖大模型来计算。

### 第三阶段：语义匹配

依赖：P2-01～P2-04；可先定义纯数据契约，再等待查询接口完成。

- [ ] **P3-01 业务语义规则落地。** 将规则版本化，支持近义表达、概念包含、材质否定、歧义和证据冲突；不要把所有分类硬编码为配件。验收：圆珠缺少配件标签仍可纳入，颜色相似不能推断材质。
- [ ] **P3-02 多路候选查找。** 组合目录字段、分类子树及有限范围全量遍历，去重并记录来源。验收：正式候选覆盖冻结的预期集合，能解释候选数量和范围。
- [ ] **P3-03 模型相关性判断。** 输出纳入/排除/待确认、证据字段和理由；必要时补读详情。冲突和未知不硬猜。验收：只能引用实际候选；缺失、重复或无效判断可检测。
- [ ] **P3-04 完整性与执行预算。** 分批评估、记录覆盖率，处理模型失败、取消和超时；未检查完不能回答“全部”。验收：部分失败不会表现为空结果或完整结果。
- [ ] **P3-05 评估是否加入语义索引。** 用案例比较现有候选查找与向量补充的漏查、误查、延迟和成本。验收：记录采用/暂缓依据；若采用，补齐索引生命周期和实时回源。

阶段出口：真实主案例及语义边界案例可评估，有明确的漏查、误查和不确定结果记录。

### 第四阶段：对话编排与 DeepSeek

依赖：P2、P3 的核心工具与结果结构。

- [ ] **P4-01 模型与 SDK 验证。** 独立助手模型配置；验证实际接口的工具调用、流式响应、多轮消息及所用 SDK 版本。验收：有最小真实调用记录，不沿用图片模型支持能力的假设。
- [ ] **P4-02 受控工具调用循环。** 注册工具、校验参数、传递认证上下文、处理结果和错误；限制轮数与预算。业务字段内容作为数据。验收：能完成主案例，模型不能新增工具或执行自由 SQL。
- [ ] **P4-03 会话与连续追问。** 会话按账号隔离；保存已确认条件、待澄清项、规则版本及结果引用。追问按需重新查询实时事实。验收：“只看圆珠”“按供应商汇总”“改为上个月”正确保留和替换条件。
- [ ] **P4-04 可追溯执行记录。** 记录必要的查询条件、工具耗时、执行状态、规则/模型版本和依据；不把密钥及不必要联系信息发给模型或写入日志。验收：可定位漏查发生在解析、候选还是判断阶段。
- [ ] **P4-05 故障与中断处理。** 区分无结果、歧义、查询失败、模型失败、未查完和用户取消。验收：可继续或重试；失败不生成虚构明细或零金额结论。

阶段出口：通过服务接口完成可追问、可追溯的完整文字查询流程。

### 第五阶段：助手界面

依赖：P4 的事件/响应契约；开始前读取当前适用的前端 skill 和 Next.js 本地文档。

- [ ] **P5-01 对话入口。** 独立助手页面、桌面/手机适配、中英文文案、流式说明、取消和重试。验收：沿用现有主题及导航，无横向溢出。
- [ ] **P5-02 结构化结果。** 后端明细直接渲染图片、名称、规格、日期、渠道商、数量、金额、库存和真实详情链接。验收：文字与表格引用同一结果集合。
- [ ] **P5-03 查询范围与完整性。** 展示生效条件、匹配依据、待确认项、分页、全部结果计数与汇总。遵守现有价格隐私设置。验收：分页不改变全量汇总，未完成状态清晰。
- [ ] **P5-04 纠正反馈。** 保存“应包含/不属于/理解错了”等反馈，关联问题、记录和规则版本；经整理确认后更新规则。验收：单次反馈不会直接改变全局定义。

阶段出口：用户能完成主问题、查看依据、打开原始记录并继续追问。

### 第六阶段：验收与语音扩展

依赖：P2～P5；先完成文字版验收，再接入语音。

- [ ] **P6-01 固定基线回归。** 对冻结快照和构造案例验证召回、误查、事实、汇总、完整性、追问及账号隔离。验收：满足案例文档门槛；记录实际结果和失败项。
- [ ] **P6-02 真实开发库联调。** 只读检查当时业务数据，记录与冻结基线的差异及原因。验收：真实模型与业务服务共同跑通；不把模拟调用当真实通过。
- [ ] **P6-03 性能与成本。** 测量候选规模、模型调用次数、响应耗时和用量，确定预算、缓存和索引选择。验收：超预算行为可见，实时事实不被过期缓存覆盖。
- [ ] **P6-04 文字版交付。** 汇总检查、已知限制、运行配置和使用说明，更新交接。发布或生产迁移按当时用户授权执行，不能由本计划推定授权。
- [ ] **P6-05 语音输入。** 选择中文 ASR，录音、权限、转写、文字修正后发送；处理渠道商和珠宝词汇。验收：语音与文字复用相同助手和会话。
- [ ] **P6-06 可选语音播报。** 根据后续需求接入 TTS，支持停止播报；明细仍可查看。验收：不影响文字操作和查询事实。

## 跨会话工作规则

### 开始一个任务

1. 阅读仓库 `AGENTS.md`、本文件、语义规则、验收案例，以及相关任务涉及的最新源码。
2. 查看 `git status --short`。当前工作区存在其他会话的账号追溯和 UI 修改，不得重置、覆盖、顺手格式化或代为提交。
3. 从未完成且依赖满足的任务中选择一项；先登记任务 ID、会话标识、开始时间和预计涉及路径。发现同一任务或共享文件已被占用时，先协调或选择独立任务。
4. 涉及 Next.js 编码前，读取 `node_modules/next/dist/docs/` 的相关指南。前端实现按当时适用 skill 执行。
5. 如需调整契约，先更新相关文档并检查受影响任务，避免不同窗口各自实现不兼容结构。

### 结束或交接一个任务

1. 按任务验收条件检查交付物；只完成设计或模拟验证时，不得勾选实现通过。
2. 修改/新增的源码单独用 Prettier 格式化，并运行 `npm run format:check`；选择必要的类型、lint 和服务层测试。简单局部改动不新增或运行 E2E。
3. 更新任务状态，记录涉及路径、验证命令/结果、未解决事项、下一项任务和契约变化；释放占用记录。
4. 未完成时写清“已做/未做/下一条可执行动作”，不能只有“进行中”。凭据、生产连接串和无关业务隐私不得写入交接。
5. 多个窗口同时修改本文件时先读取最新版本，保留已有记录；详细交接可分别追加到本目录下的 `ai-assistant/handoffs/`，再将链接加入本文件。
