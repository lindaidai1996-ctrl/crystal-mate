## 目标与范围

用户可以用自然语言查询商品、物料、渠道商、采购记录和当前库存，支持继续追问。首个端到端里程碑：

> 帮我找下这个月我去荔湾广场买了哪些绿松石相关的配件。

必须识别“配件/配饰”的表达差异，纳入属于制作物料的绿松石圆珠等记录，不能强制要求同名标签。最终结果能解释纳入依据，并关联真实业务明细。

首版交付文字对话、语义匹配、只读查询、连续追问、结果明细、完整性状态、业务汇总和回归验证。语音转文字随后接入同一条查询链路，语音播报再独立增加。

## 技术方案与约束

1. 继续使用现有 Next.js、TypeScript、Prisma、PostgreSQL、Zod、Ant Design 和 DeepSeek。
2. 优先评估 AI SDK 管理工具调用和流式对话；依赖引入前验证实际模型/接口兼容性。自行实现受控调用循环也可，记录选型依据即可。暂不预设 LangGraph、Dify 或 MCP 为依赖。
3. 查询链路：理解问题 → 解析业务实体和语义范围 → 找全候选 → 基于字段证据判断 → 查询真实明细 → 后端汇总 → 展示结果和口径。
4. 时间、地点、权限作为受控查询边界；“配件”等软语义不能在召回前变成必须存在的标签。即使硬条件来自模型，也要由后端校验。
5. 范围较小时分页读取并检查全部候选。大范围结合名称、别名、分类、标签、备注召回；任何截断都要暴露未完成状态。不得用 Top-K 或第一页冒充全部。
6. 语义检索是否引入，由验收样例中的漏查情况决定。后续引入向量索引时，明确生成、更新、删除、版本和过期回退策略；实时事实仍读取业务库。
7. 模型只能调用注册的业务工具，不能执行自由 SQL。查询、鉴权、数据范围校验、金额与数量计算都由后端完成。
8. 语义结论分为纳入、排除、待确认；未评估单独记录。模型必须引用返回过的实体 ID 和字段证据，不能生成不存在的记录。
9. 会话归属使用认证账号；会话消息和筛选条件不等于业务数据归属。“录入者”不等于“采购人”。
10. 本计划中的路径和接口名称是建议，落地时结合当时源码调整并更新文档。不要将初始快照当成持续不变的业务数据。

## 任务清单

### 第一阶段：业务口径与验收基线

- [x] **P1-01 核对现有结构。** 阅读数据模型、日期筛选、采购汇总、检索、鉴权及并行账号追溯变更。交付：字段映射与源码索引。
- [x] **P1-02 明确语义规则。** 区分用户已明确要求、实施默认值和待决定事项；覆盖配件、配饰、圆珠、材质、地点、日期、采购人、库存与金额。交付：业务规则文档。
- [x] **P1-03 取得真实开发数据基线。** 只读事务提取分类、标签、区域、地点依据及有界范围的全部候选；不读取生产库。交付：JSON 快照及提取方法说明。
- [x] **P1-04 整理真实与构造案例。** 真实例子有记录 ID、完整候选范围和精确预期；构造案例明确标注，不能写入业务库。交付：验收案例文档。
- [x] **P1-05 定义验收方法。** 分开评估召回、误查、事实、汇总、完整性和追问；明确尚未运行助手评估。交付：验收门槛与评估记录格式。
- [x] **P1-06 完成交接。** 更新状态、下一任务、并发变更注意项、格式检查和验证限制。交付：本文件交接记录。

阶段出口：后续会话无需重新询问需求，就能按既定规则实现查询工具；真实案例与构造案例可区分，期望结果可核对。

依赖：P2-01～P2-04；可先定义纯数据契约，再等待查询接口完成。

- [x] **P3-01 业务语义规则落地。** v1 确定性策略支持制作用途近义/形态包含、材质/用途区分、否定、歧义及字段冲突；真实证据绑定，未知或未覆盖表达保留待确认。圆珠无配件标签、颜色/仿制负例和冻结 11 条通过；模型判断仍待 P3-03。见[规则说明](ai-assistant/semantic-policy.md)。
- [x] **P3-02 多路候选查找。** 独立认证服务联合名称/别名、分类/真实祖先、标签、备注与完整有界范围后备，按目录/采购身份去重并保留真实来源及全量计数。冻结与开发库主案例 44 条完整召回，覆盖 11 条预期，无重复。最多 5000 条，超限明确失败；大范围优化/预算恢复仍待 P3-04。见[说明](ai-assistant/semantic-policy.md)及[交接](ai-assistant/handoffs/2026-11-16-p2-06-p3-01-02.md)。
- [x] **P3-03 模型相关性判断。** 认证快照、最小语义 DTO 和严格 JSON 输出，后端按原证据索引还原并复用 v1 校验，拒绝虚构/错配/重复/改证据，保留分歧/冲突与未评估。冻结核心与构造边界真实模型各三次通过；见[执行契约](ai-assistant/model-evaluation.md)及[交接](ai-assistant/handoffs/2026-11-16-p3-03-05.md)。
- [x] **P3-04 完整性与执行预算。** 有界范围内分批判断、遍历/判断累计覆盖率，累计调用/token/条数及每步/单次预算、失败/超时/取消/继续/重试与 revision 防旧响应覆盖。故障/跨页/重试以服务 mock 验证；真实模型为完整有界批次。仍不支持超过 5000 行的数据库分块召回，不把上限提高或部分成功称全量。见[执行契约](ai-assistant/model-evaluation.md)。
- [x] **P3-05 评估是否加入语义索引。** 当前冻结/构造完整后备及词路联合无预期正例漏查，真实模型约 10 秒/44 行，记录实际 token 用量及误查/差异；暂缓索引，先优化输入重复和评估更大负载。不伪造向量对照数据；生命周期前置要求、限制和重评触发条件见[索引评估](ai-assistant/semantic-index-assessment.md)。

阶段出口：真实主案例及语义边界案例可评估，有明确的漏查、误查和不确定结果记录。

### 第四阶段：对话编排与 DeepSeek

依赖：P2、P3 的核心工具与结果结构。

- [x] **P4-01 模型与 SDK 验证。** 独立助手模型配置，移除相关性对图片模型变量的回退；真实验证普通响应、强制单个函数调用及固定工具结果、普通文本 SSE、多轮历史。选择原生 fetch，不新增 SDK；SDK 未安装/未实测，不声称不兼容。版本、参数、逐次耗时/用量、DNS 失败及未测范围见[报告](ai-assistant/model-compatibility.md)与[交接](ai-assistant/handoffs/2026-11-17-p4-01.md)。未实现业务工具循环或会话。
- [x] **P4-02 受控工具调用循环。** 注册工具、校验参数、传递认证上下文、处理结果和错误；限制轮数与预算。业务字段内容作为数据。验收：能完成主案例，模型不能新增工具或执行自由 SQL。
- [x] **P4-03 会话与连续追问。** 会话按账号隔离；保存已确认条件、待澄清项、规则版本及结果引用。追问按需重新查询实时事实。验收：“只看圆珠”“按供应商汇总”“改为上个月”正确保留和替换条件。
- [x] **P4-04 可追溯执行记录。** 记录必要的查询条件、工具耗时、执行状态、规则/模型版本和依据；不把密钥及不必要联系信息发给模型或写入日志。验收：可定位漏查发生在解析、候选还是判断阶段。
- [x] **P4-05 故障与中断处理。** 区分无结果、歧义、查询失败、模型失败、未查完和用户取消。验收：可继续或重试；失败不生成虚构明细或零金额结论。

阶段出口：通过服务接口完成可追问、可追溯的完整文字查询流程。

### 第五阶段：助手界面

## 跨会话工作规则

### 开始一个任务

1. 阅读仓库 `AGENTS.md`、本文件、语义规则、验收案例，以及相关任务涉及的最新源码。
2. 查看 `git status --short`。当前工作区存在其他会话的账号追溯和 UI 修改，不得重置、覆盖、顺手格式化或代为提交。
3. 从未完成且依赖满足的任务中选择一项；先登记任务 ID、会话标识、开始时间和预计涉及路径。发现同一任务或共享文件已被占用时，先协调或选择独立任务。
4. 涉及 Next.js 编码前，读取 `node_modules/next/dist/docs/` 的相关指南。前端实现按当时适用 skill 执行。
5. 如需调整契约，先更新相关文档并检查受影响任务，避免不同窗口各自实现不兼容结构。

### 结束或交接一个任务

1. 按任务验收条件检查交付物；只完成设计或模拟验证时，不得勾选实现通过。
2. 修改/新增的源码单独用 Prettier 格式化，并运行 `npm run format:check`；选择必要的类型、lint 和服务层测试。简单局部改动不新增或运行 E2E。
3. 更新任务状态，记录涉及路径、验证命令/结果、未解决事项、下一项任务和契约变化；释放占用记录。
4. 未完成时写清“已做/未做/下一条可执行动作”，不能只有“进行中”。凭据、生产连接串和无关业务隐私不得写入交接。
5. 多个窗口同时修改本文件时先读取最新版本，保留已有记录；详细交接可分别追加到本目录下的 `ai-assistant/handoffs/`，再将链接加入本文件。
