# 图片缓存与缩略图

图片继续保存在私有 COS 桶，浏览器通过需要登录的 `/api/images/...` 读取。数据库中保留原始 URL，不需要迁移现有图片或修改 COS 对象元信息。

- 浏览器：成功响应设置 `private, max-age=2592000, immutable`，有效期 30 天。相同 URL 在缓存有效期内通常不发请求；浏览器清理或驱逐缓存、强制刷新时仍可能请求服务器。
- 服务器：原图及缩略图缓存在私有磁盘目录，命中后不向 COS 发起 HEAD 或 GET。缓存也保留 30 天，默认总容量 512 MB，写入前按生成时间清理过期及最旧的文件。并发读取同一图片在单个进程内合并为一次加载，失败和不完整下载不缓存。
- 协商缓存：原图和不同尺寸各有基于内容的 ETag。携带匹配的 `If-None-Match` 时返回无正文的 304；仍先检查登录权限。服务器缓存命中时不会为校验 ETag 查询 COS。
- 缩略图：`?w=128` 用于小缩略图，`?w=640` 用于图库和悬停预览。按需生成 WebP，保留完整画面、透明背景和比例，不放大小图。完整预览、裁剪和识别继续读取原图。首次生成会读取一次 COS 原图，后续其他尺寸复用缓存。为控制内存，同一进程串行处理缩略图；超过 4000 万像素或无法转换的图片回退到原图，并使用实际图片类型响应。

## 部署

`MEDIA_CACHE_DIR` 默认是项目下的 `.cache/images`；`MEDIA_CACHE_MAX_MB` 默认是 `512`。缓存目录不能放在 `public` 下或通过 Web 服务器公开。目录必须可写；磁盘不可用时请求仍可读取存储，但不能保证节省后续 COS 请求。默认目录已从 Git 和 Docker 构建上下文排除。

生产 Compose 使用独立的 `image_cache` Docker 卷挂载到 `/app/.cache/images`，重建容器后仍能复用。正常重新构建并启动应用即可启用，不需要数据库迁移或改变桶的访问权限。卷和宿主机应留有额外磁盘余量；容量限制按缓存文件正文计算，目录、文件系统及临时写入存在少量额外开销。多实例请分别使用独立目录或卷，容量控制及请求合并按单个进程管理，不让多个写入进程共用同一目录。

缓存成立的前提是图片地址不可变。当前上传和替换会生成新的 UUID 地址；不要在 COS 控制台覆盖同名文件。若手动覆盖或删除 COS 对象，服务器已有副本可能继续保留至缓存过期，浏览器已有副本也会保留至过期。需要立即撤回内容时应使用新的 URL 并清理服务器缓存；已下载到浏览器的副本无法由服务器立即撤销。

## 验证

开发者工具关闭「Disable cache」，通过页面正常导航重复查看同一图片；Size 应显示 memory cache 或 disk cache。单看 Status 200 不能判断是否下载。强制刷新、首次打开或浏览器缓存被驱逐时可能仍会请求服务器。

检查响应头中的 `Cache-Control` 和 `ETag`，列表图片 URL 应带 `?w=128` 或 `?w=640`。携带 ETag 再请求时应返回 304。COS 请求统计应在服务器缓存预热后下降；第一次预热、新图片、缓存过期或被容量限制清理后仍需要读取 COS。
