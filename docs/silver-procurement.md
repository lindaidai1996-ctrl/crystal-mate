# 银料采购台账与 Excel 导入

采购台账位于统一计价的独立子页面 `/admin/material-pricing/purchases`，通过顶部“采购明细”导航进入，沿用当前计价组，也可清空组筛选查看全部计价组。台账复用既有物料、供应商、批次和采购明细，不按日期或供应商重复创建物料。采购物料必须为克单位且已关联计价组，不要求组已发布或启用。

## 成本、折扣与库存

- 新台账在原 `purchaseQuotedGramPrice` 保存折前报价，以 `purchaseQuotePurpose=BEFORE_DISCOUNT` 标记；旧数据默认 `LEGACY`，不推定为折前价格。
- 实际克价为实付除以重量；实际折扣为实付除以重量和折前克价的乘积，再乘10显示为“8.50折”。Decimal计算，实付取到分，台账实际克价显示四位、折扣两位，不用舍入后克价算折扣。
- 折前模式关闭原报价/金额/重量三项互算。报价可缺省，零报价不计算折扣，真实零实付有效。输入折扣生成待保存实付，修改实付再计算折扣。
- 各银料明确填写实际分摊金额，首版不推断整单优惠、其他物料、运费等分摊。统一计价始终汇总真实实付和采购重量，折前报价不进入成本或货损估算。
- 新采购默认 `initialStock=FULL`，全部重量入库；历史采购可选 `UNKNOWN`。Excel导入固定采用未知剩余量，采购重量完整保存、余量为null。修改采购重量保留未知；已知余量按采购差额修正，越界拒绝。盘点使用原入口并留审计。

## 批次与编辑

物料管理中的统一计价物料在卡片、桌面表格和手机列表使用紧凑计价组摘要，不逐条展开采购批次或批次旧售价；停用但仍关联组的物料同样处理，可通过“查看采购台账”查看该组全部明细。普通物料维持批次展示；库存摘要和盘点入口保持完整。AI 助手影响：无需同步，本次只调整列表展示，不改变采购、价格计算、库存事实或权限。

每次录入、每个Excel原始行分别创建 `purpose=PRICING` 批次；同日同供应商不合并。旧批次为GENERAL。普通批次列表默认只收起明确标记、非空、仅含已关联按克物料的批次；混有普通物料或成品、解除组关联或未标记的旧批次继续显示。可以切换查看统一计价采购或全部。

### 批次选择与命名（2026-11-23）

物料新增/编辑、物料图片导入、成品进货及批量移入批次共用批次选择器。默认收起纯统一计价采购批次，勾选“显示统一计价采购”后展示全部；混合批次及当前已选批次始终保留。明确标记 `PRICING` 的选项和已选值显示“统一计价采购”标签，搜索仍按批次名称匹配，不用名称前缀判断批次用途。

统一计价采购新增及采购台账编辑时，批次名称使用 `计价组名-YYYY-MM-DD-渠道商名称`。多个计价组或渠道商按首条采购明细的顺序取第一个名称并加“等”，按关联 ID 去重；历史明细按创建时间、ID 排序。超长名称部分缩写，保留日期；重名追加 `（2）`、`（3）`，不合并采购。数据库事务锁及精确的名称冲突重试防止并发创建重名批次；普通批次在台账编辑时保留原名称。

历史 `AG-日期-随机编号` 批次通过专用脚本一次性改名，仅处理明确标记 `PRICING` 且所有明细仍关联按克计价组的系统生成名称。脚本默认只读预览，`--apply` 才在单个事务中改名；写入前备份原名称，并校验除批次名称/更新时间和审计以外的业务表内容指纹一致。重复执行不再改动已命名批次，不修改普通批次、自定义名称或批次 ID。只支持明确验证的开发库：

```bash
node scripts/with-dev-db.mjs tsx scripts/rename-pricing-batches.ts --dev
node scripts/with-dev-db.mjs tsx scripts/rename-pricing-batches.ts --dev --apply
```

**AI 助手影响：无需同步助手代码。** 本次只改批次选择展示及真实批次名称，采购关系、金额、库存和权限不变；助手现有查询读取当前名称，已保存的历史回答不重写，批次用途仍未接入独立自然语言查询。验证边界：类型、格式、定向 lint 与采购单元/隔离数据库检查；不以这些检查代替真实账号浏览器或生产部署验证。

2026-11-23 验证：22 项采购相关单元/接口检查、10 项独立测试库事务检查通过，覆盖选中批次保留、混合/历史批次可见、多组/多渠道命名、并发重名及编辑后命名；类型、定向 lint、全仓格式检查通过。开发库已改名 107 个历史批次，业务表指纹核对一致，原名称备份及结果位于 `backups/pricing-batch-names/2026-11-23T02-16-22-145Z/`。未修改生产库，未运行 E2E、生产构建或真实浏览器流程。

台账支持计价组、供应商、日期筛选与月份/供应商汇总，展开看明细。供应商筛选仅列出所选计价组与日期范围内实际有采购的渠道商，新增/编辑采购的渠道选择仍用完整字典。趋势、重量/实付占比与渠道商报价分析见独立的[采购分析](material-unified-pricing.md#采购分析与渠道商筛选2026-11-20)子页面。未知金额或重量单独提示，当前完整查询上限5000条，超限报错。台账展示所有采购，未来日期和不完整成本是否纳入定价仍由原计价规则决定。

编辑按整次采购更新共用日期、供应商和备注，各行保留身份，不自动新增或删除行。指纹与串行化事务阻止覆盖并发修改，保留销售配置、图片及盘点。混合类型或多供应商批次从原物料详情编辑。

## 导入工作流

1. 选择不超过20MB的.xlsx，每次最多300个原始采购行。默认“总账”，每次一个工作表，可修改最后表头行和列映射。
2. 默认日期A、渠道N、整单实付L；S925为B/C/D/P，精工925为E/F/G/Q，清迈银为H/I/J/R，分别对应重量、原价、折后价和银料实付。空或零重量不生成采购。
3. 供应商全名唯一匹配时预选，不合并不同渠道写法；物料只预选模板中的唯一同名项，须在预览确认。支持明确新建供应商或在既有计价组/分类下新建尚无采购的按克物料。
4. 金额优先用源重量乘源折后价取到分，缺折后价时采用源银料实付。与源银料金额不符时需修正或明确核对当前金额。整单实付仅保留核对，不重复计入各银料。
5. 保留单元格、公式、缓存和日期体系，不执行任意公式或访问外链。缺日期不向上填；非法值、缺映射的行必须修改或跳过。原始单元格和源金额不可通过草稿修改覆盖。
6. 保存预览草稿不创建采购，草稿可恢复。文件SHA-256与工作表唯一确定草稿，逐行持久回执防重复。不同文件的同日同供应商、物料、重量和金额会提示疑似重复，核对允许后可录入另一笔真实采购。
7. 选择可提交行确认。每个原始行的全部银料与回执在一个事务内提交，失败整行回滚，其余行继续，重试不重复已成功行。

### 后台导入与进度

确认后服务端保存本次所选行并启动后台导入，弹窗只等待任务启动。进度区显示百分比、已处理/总行数、成功与失败行数及失败原始行号；处理进度包含成功与失败，结束时仍明确提示失败行未写入。失败行可核对、修改后重新选择导入。

导入中可以点击“后台导入，关闭窗口”，也可以离开页面或关闭浏览器。重新打开“Excel 批量导入”时优先恢复正在运行或中断的任务，从历史草稿可切换查看其他任务。进度来自数据库，页面每1.5秒查询；离开页面会停止查询，服务端仍继续执行。查询断网会自动重试，不把网络失败当作导入失败。

任务使用 Next.js `after` 在当前 Node 服务进程中执行，不需要浏览器保持打开，也不是独立的常驻队列。进度、失败、采购与回执逐行持久保存；同一草稿的并发启动只创建一个任务，运行期间禁止修改该草稿或逐行手动提交。每行使用数据库锁、运行令牌与60秒租约，恢复后旧回调不能继续写入。

服务重启、基础设施故障或单次后台执行达到约4分钟时保留进度并显示中断（强制停止时，租约过期后显示），点击“继续导入剩余行”处理未完成行，已成功或已记录失败的行不重复执行。生产平台需支持 `after` 的响应后执行和至少300秒路由时限；服务重启后不自动恢复任务。

## 接口与迁移

- `/api/material-pricing-purchases`：GET台账及匹配选项、POST新增；`/{batchId}` GET编辑数据/指纹、PATCH修改；`/catalog` POST明确新建关联组的按克物料。
- `/api/material-pricing-imports`：GET最近30份草稿、POST创建/恢复；`/{id}` GET校验预览、PATCH带版本修改未提交行；`/{id}/commit` POST带版本及原始行号提交。
- `/{id}/run`：POST `{version,rowNumbers}` 启动后台任务，或 `{version,resume:true}` 继续中断任务，返回202与持久进度。读取接口只返回进度，不暴露服务端运行令牌。
- 沿用管理员认证、写入同源检查、no-store、价格隐私及审计。草稿原始金额JSON不进入审计明文展示。
- `20261120010000_material_pricing_purchases` 仅增加批次用途、报价标记和导入草稿表/审计，不修改既有金额、重量和库存，不自动创建业务记录或关联物料。
- `20261120020000_silver_import_background` 只给导入草稿增加可空的任务状态字段，不改变既有草稿、采购或库存。部署新版代码前须应用此迁移。

## AI 助手影响与验证

**AI 助手影响：已同步现有采购/库存口径及能力边界。** 助手采购事实仍取真实实付，库存继续区分未知与零；修改采购不再把未知库存填为全部重量。折前报价、折扣、批次用途和导入草稿/回执不进入模型事实，首版不提供这些字段的自然语言查询，不覆盖冻结验收基线。
