# DIY 商品名片

商品列表中，DIY 商品的操作区提供「商品名片」入口。同一商品可以保存多份名片，分别选择制作记录、模板、图片、文案和品牌信息。

## 使用方式

1. 新建名片，选择对应的 DIY 制作记录。默认最新一条，自动选取当前商品前三张图片。
2. 选择自然雅致、杂志感或东方诗意模板。保留 1–3 张商品图，调整顺序；图片裁切只作用于当前名片。
3. 修改展示名称、主要物料和短文。文案可手动填写，也可生成三条候选后选择、编辑。
4. 按需勾选完整对客报价明细，填写品牌名、微信号，上传 Logo 和二维码。可使用项目现有 Logo，也可将品牌配置保存为今后新建名片的默认值。
5. 点击「更新预览」检查实际 PNG，点击「保存并导出 PNG」保存并下载。内容发生修改后，预览会标记待更新。

未完成的文案可以先保存、预览；正式导出前须填写主要物料和哲理短文。

名片标题用于区分不同名片和命名下载文件，不印在图片上。基础图片宽 1080 像素，高度随实际内容调整；店铺信息与二维码紧随文案排列，长文字和明细向下延伸，不缩小商品主体或截断条目。最多 12 项主要物料、180 字手动文案、100 行费用，最终图片高度不超过 14000 像素；超限明确报错。

预览生成时复用商品列表图片的扫光骨架效果；更新已有预览时保留原图占位高度，避免布局跳动。动态高度排版使用模板版本 2，底层保留版本 1 的渲染能力；页面中的保存和导出会将旧模板版本升级到新版，即使文案没有修改也先保存再导出，确保与编辑预览一致，缓存按模板版本隔离。

「作品图片」中的裁切缩略图按原图尺寸与实际裁切范围计算比例，在正方形位置内居中留白，不再把非正方形裁切区域拉伸；切换模板或重排图片后仍以已保存裁切区域的真实比例展示。

## 快照和金额

- 保存的展示名称、主要物料、文案、图片、品牌配置及对客报价独立于业务数据。源商品改名、改价、移除图片不会覆盖已有名片。
- 「更新商品数据」先展示当前内容和来源内容，可分别更新名称、主要物料、图片、整份报价。导入文字后仍可继续编辑；哲理短文不被刷新操作覆盖。
- 明细按单件展示，复用 `customerDiyDetails` 字段白名单。物料、蛋面、银料和其他费用均使用对客价格；手工设计费按制作数量分摊，以整数分计算、四舍五入。
- 明细合计必须与制作记录的单件报价一致；缺少报价或历史金额不一致时，不允许带明细导出，仍可导出无金额版本。修改报价需先编辑 DIY 配置，再主动更新名片。
- 制作记录删除后，名片保留报价和图片快照，仍能编辑、复制和导出；也可选择其他制作记录。
- 每次写入校验名片版本；发生并发修改时返回 `CARD_CONFLICT`。选中来源在保存期间变化时返回 `CARD_SOURCE_CHANGED`，不静默覆盖。

## 服务端与部署

新增 `ProductCard`、`ProductCardAsset`、`ProductCardBrandSettings`。名片及品牌配置沿用现有管理员鉴权和数据库审计；品牌资产没有商品归属，审计单独归属资产本身。开发迁移只应用本功能的两条迁移，不代为执行工作区内其他功能的待执行迁移。

接口入口：

- `/api/products/:id/cards`：名片列表、新建，以及所选制作记录的对客来源数据。
- `/api/product-cards/:id`：读取、版本校验编辑、删除；子路径 `/copy` 复制，`/png` 预览或下载保存的 PNG。
- `/api/product-cards/preview`：编辑中内容的真实 PNG 预览；只接收配置，报价始终由服务端取得。
- `/api/product-cards/copywriting`：生成三条候选，仅接收名称、主要物料、模板。
- `/api/product-card-assets`、`/api/product-card-assets/:id`：上传品牌图和鉴权读取私有资产；不允许任意 URL 或本地文件路径。
- `/api/product-card-brand`：带版本校验的品牌默认配置。

商品图在首次选用时复制为独立、不可覆写的 PNG；Logo 和二维码也采用独立私有资产。COS 使用 `product-cards/assets/`，本地开发使用 `.data/product-cards/assets/`，不放在公开的 `public/uploads`。私有源图与名片资产需要一同备份。当前不自动清理未引用资产，避免误删仍用于其他版本或品牌默认配置的图片；删除名片只删除名片记录。

Satori 排版、Resvg 输出 PNG，Sharp 处理方向、裁切和图片尺寸。字体为 Noto Sans SC Regular、Noto Serif SC Regular，来自 [Noto CJK](https://github.com/notofonts/noto-cjk)，使用 SIL Open Font License；源文件和许可证放在 `assets/product-card-fonts/`，随 standalone 和 Docker 镜像打包，不依赖操作系统字体或在线字体服务。

PNG 在 `.cache/product-cards/` 按内容、明细开关及模板版本缓存，最多保留 60 个文件，每张最多 24 MiB。该缓存可重建，无需与业务资产一起备份；容器重建后重新渲染。单进程串行渲染，最多四个排队请求，超限返回 `CARD_RENDER_BUSY`。部署新模板时须保留旧模板渲染版本或显式迁移，不能只替换旧模板的实现而复用旧版本号。

## DeepSeek 配置

`PRODUCT_CARD_API_KEY`、`PRODUCT_CARD_BASE_URL` 留空时复用 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`；`PRODUCT_CARD_MODEL` 默认 `deepseek-flash`，不复用视觉模型名称。调用超时 30 秒，每账号同一时间一个请求，最小间隔三秒。

仅在主动生成或换一组文案时调用模型。已保存文案在预览、下载、复制时直接复用。模型输入不包含价格、成本、采购信息或内部备注；提示词约束原创、克制、不虚构功效和名人出处。服务端校验三条候选各 30–60 字且互不重复；内容仍允许人工修改。服务不可用时保留编辑内容，可手动填写。

## AI 助手影响与验证

**AI 助手影响：无需同步查询能力。** 本功能没有改变库存扣减、业务报价或价格隐私口径，未将名片和品牌配置接入助手证据字段。助手暂不查询或编辑名片；文案生成是独立接口，不使用助手会话或受控工具循环。

`scripts/check-product-cards.ts` 只读开发数据库与商品图，生成三模板 × 三种图片数量 × 有无明细共 18 份 PNG，以及 80 字名称、180 字短文、30 行明细的长内容样例，输出到 `.cache/product-card-qa/`。可传商品 ID 指定素材，未传时选择最近更新且有图片和制作记录的 DIY 商品。

```sh
node scripts/with-dev-db.mjs tsx scripts/check-product-cards.ts [商品ID]
npx vitest run tests/unit/product-cards-quote.test.ts tests/unit/product-cards-service.test.ts tests/unit/product-cards-copy.test.ts
npm run typecheck
npm run format:check
```

视觉样例中的测试文案用于验证布局，不会写回商品，也不代表模型真实生成内容。生产发布和生产数据库迁移单独安排。
