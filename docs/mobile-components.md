# 移动端公共组件

移动端断点统一为 `767px`。组件沿用 `uiTheme` 的颜色、字体和 44px 控件高度。

## 筛选

`responsive/mobileFilters.tsx` 提供 `MobileFilters<T>` 和 `FilterChoices`。

- 桌面端渲染 `children`，手机端渲染搜索框和横向筛选入口。
- 每个入口通过 `MobileFilterGroup<T>` 提供标题、选中态、计数、选项和重置逻辑。
- 打开面板时复制当前条件；选项修改只影响草稿；点击确定才调用 `onApply`。
- 关闭、遮罩或 Escape 放弃未确认的草稿。重置只修改当前面板的条件，仍需确定。
- `valid` 可以禁用不完整条件的提交。时间筛选提供快捷范围和单月日历，默认从开始日 00:00 到结束日 23:59；需要时展开调整时分，保留北京时间的协议格式。
- 商品列表通过 `productListFilters.tsx` 接入分类、价格排序、来源、库存、上下架、标签、蛋面款式、营销状态和创建时间。
- 物料列表通过 `materialListFilters.tsx` 接入多级分类、来源和创建时间。

页面在 `onApply` 中统一更新业务条件并回到第一页。无变化的提交不应触发加载状态。

`SearchFilterRow` 将搜索框和 `ResetFiltersButton` 保持在同一行，搜索框自动占据剩余空间，重置不单独占行。该组合可以作为 `MobileFilters` 的 `search` 或普通筛选区的子节点。页面负责清空搜索、日期、分类等全部业务条件和排序，回到第一页并自动查询；服务端列表需要保证条件已为空时点击也能重新查询。画廊/列表切换始终放在工具栏右侧。

## 列表顶部操作

`ListPageActions` 通过 `primary` 指定新建等主要操作，辅助操作作为 `children` 传入。手机端主要操作独占首行，草稿箱、导入、分类管理等排列在下一行；桌面端主要操作位于辅助操作之后。

## 表格与画廊

`PaginatedTable` 在手机上把普通表格转换为“字段名 / 内容”的纵向行，继续由 Ant Design 处理客户端排序、筛选和分页。含展开、选中、分组表头、虚拟滚动、自定义表格组件或汇总的表格保留原布局。

服务端分页列表可通过 `mobileRender(record, index)` 提供摘要卡片，商品、蛋面、物料列表已接入。`mobileRender` 必须使用已经分页的记录以及受控 `pagination.current`、`total`、`onChange`；行选择等操作由摘要卡片提供。

需要强制保留横向表格时使用 `mobileLayout="scroll"`。

`CatalogGallery` 在手机上显示双列小卡片，低于 360px 时回到单列。`MobileDetails` 在手机上折叠次要内容，在桌面端直接显示内容。商品售价、库存、名称和编辑入口留在折叠区域外；物料的多批次价格集中在“批次价格”中展开查看。

## 编辑与弹层

`EditorActions` 包裹原有取消、草稿和保存按钮，桌面端保持普通操作区，手机端固定到底部并预留占位，兼容底部安全区。应保持在原有 `Form` 内，使 `htmlType="submit"` 正常工作。

`ResponsiveDrawer` 保留 Ant Design Drawer 的属性，手机端使用全屏底部抽屉；`ResponsiveModal` 在手机端使用底部弹层、可滚动内容和独立按钮区。上传、保存期间的禁止关闭逻辑仍由调用方控制。

目前已接入商品、物料、批次、渠道商、库存调整、来源记录、物料选择以及分类、标签、蛋面款式等编辑入口。图片裁剪等专用弹层保留原组件。

## 验证范围

使用不连接数据库的实际公共组件预览检查手机及桌面尺寸、筛选草稿与确认、取消、重置、多级分类、日期范围、客户端排序和分页、底部保存栏及弹层尺寸。预览采用明确的占位内容；这不能替代真实账号、真实业务数据和手机软键盘下的完整业务验证。

`CompactFields` 按内容组织短数值字段：手机上尺寸使用三列（低于 360px 时两列），进货、售价和成本使用两列。名称、渠道商、批次、备注继续保留完整宽度；“应用到宽高”放在尺寸标题旁。
